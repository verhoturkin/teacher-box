# Эксплуатация Teacher Box

Документ для учителя или администратора, который развернул портал на своём сервере.
Все настройки — переменные окружения в файле `.env` (образец — [`.env.example`](../.env.example));
с версии 1.5 администратор меняет их и в интерфейсе («Настройки», [ADR-0016](adr/0016-admin-settings.md)).

## Данные

Всё состояние портала хранится в одном каталоге — `/data` в контейнере (Docker-том
`teacherbox-data`), `./backend/data` при локальном запуске:

| Путь | Что там |
|---|---|
| `db/` | база данных H2 |
| `files/` | вложения домашних заданий (`homework/`), картинки досок (`boards/`) |
| `keys/` | ключ подписи токенов (если не задан `TEACHERBOX_SECURITY_JWT_SECRET`) |
| `backups/` | резервные копии |
| `restore/` | архив для восстановления при следующем запуске |
| `config/settings.properties` | настройки, заданные администратором в интерфейсе (важнее `.env`, не входят в копии) |

## Резервные копии

- Копия создаётся **каждую ночь** (`TEACHERBOX_BACKUP_CRON`, по умолчанию в 03:30 по времени
  `TEACHERBOX_TIMEZONE`), хранятся последние `TEACHERBOX_BACKUP_KEEP` копий (по умолчанию 7).
- Вручную: «Настройки» → «Резервные копии» → «Создать копию сейчас». Там же копии можно скачать.
- Архив `teacherbox-<дата>-<время>.zip` содержит `database.sql` (полный SQL-дамп базы,
  переносимый между версиями H2), каталог `files/` и `manifest.properties`.
- **Храните копии вне сервера**: скачивайте их или копируйте каталог `backups/` в облако —
  копия на том же диске не спасёт от его поломки.

Скопировать все копии с сервера:

```bash
docker compose -f compose.single.yaml cp app:/data/backups ./teacherbox-backups
```

### Копии досок

Отдельно от копий портала у каждой доски Excalidraw есть свои копии — в базе, внутри общей копии:

- **ежедневные** — `TEACHERBOX_BOARDS_BACKUP_CRON` (по умолчанию `0 0 3 * * *`, в 03:00 по времени
  `TEACHERBOX_TIMEZONE`; `-` — выключить) копирует каждую доску, изменённую после её прошлой
  ежедневной копии; хранятся последние `TEACHERBOX_BOARDS_BACKUP_KEEP` (по умолчанию 7) на доску;
- **копии учителя** — «Доски» → «Резервные копии» (в строке доски или на самой доске) → «Сделать
  копию», до 20 на доску.

«Восстановить» возвращает рисунок копии и сначала сохраняет текущий рисунок копией учителя — так
восстановление можно отменить. Открытые у учеников доски подхватят его в течение нескольких секунд.
Картинка доски хранится, пока на неё ссылается рисунок или любая копия; удаление доски удаляет её
рисунок, копии и картинки.

### Восстановление из интерфейса

Учитель («Настройки» → «Резервные копии») и администратор («Копии») восстанавливают любую копию
из списка кнопкой «Восстановить» с подтверждением паролем. Портал:

1. проверяет архив (формат и версию: копию более новой версии портала не восстановить);
2. делает копию текущего состояния — «перед восстановлением» (её не удаляет ротация);
3. кладёт архив в `restore/` и перезапускается — контейнер поднимается сам
   (`restart: unless-stopped` в обоих вариантах compose; в образе `TEACHERBOX_BACKUP_RESTART=true`);
4. при старте восстанавливает копию (см. ниже) и показывает итог в том же окне.

Без Docker (`TEACHERBOX_BACKUP_RESTART=false`) портал не перезапускается сам: копия будет
восстановлена при следующем запуске. После восстановления войдите с паролем, который действовал на
момент копии. Администратор не скачивает копии: в них данные учеников.

### Восстановление вручную

1. Положите архив в каталог `restore/` данных:
   ```bash
   docker compose -f compose.single.yaml cp teacherbox-20260925-033000-000.zip app:/data/restore/
   ```
2. Перезапустите портал: `docker compose -f compose.single.yaml restart`.
3. При старте, до открытия базы, портал:
   - переносит текущие `db/` и `files/` в `restore/previous-<время>/` (на случай отката);
   - восстанавливает базу из `database.sql` и файлы из `files/`;
   - переносит архив в `restore/applied/`.
4. Если восстановление не удалось, прежние данные возвращаются на место, архив переносится в
   `restore/failed/`, портал запускается как раньше; причина — в журнале и в окне восстановления.

Если в `restore/` несколько архивов, восстанавливается последний по имени (самый новый).

## Полный сброс

«Настройки» → «Полный сброс» (только учитель, с паролем и словом «СБРОСИТЬ») удаляет все данные
портала: учеников, группы, занятия, оплаты, задания и файлы, уведомления, подключения мессенджеров
из интерфейса, комнаты, доски, историю ИИ, подключения Google и Яндекса, название и адрес портала.
Остаются учётные записи учителя и администратора с паролями, резервные копии и журнал сервера.
Перед сбросом создаётся копия «перед сбросом» (её не удаляет ротация) — из неё всё можно
восстановить. Боты и ключи из переменных окружения продолжают работать. После сброса снова
открывается первоначальная настройка.

## Безопасность

- Портал рассчитан на работу **за HTTPS** (reverse proxy: Caddy, nginx, Traefik). Cookie сессии
  получает флаг `Secure`, когда прокси передаёт `X-Forwarded-Proto: https`.
- Доски Excalidraw работают в реальном времени через WebSocket (`/api/public/boards/live`). Caddy и
  Traefik пропускают его сами; в своём nginx перед порталом добавьте в `location /api/`
  `proxy_http_version 1.1;`, `proxy_set_header Upgrade $http_upgrade;` и
  `proxy_set_header Connection "upgrade";` (или через `map`, как в `docker/nginx/default.conf.template`).
  Без этого доски работают, но чужие изменения видны с задержкой в несколько секунд, а курсоров нет.
- Заголовки: Content-Security-Policy (без inline-скриптов), `X-Frame-Options: DENY`,
  `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` (камера, микрофон и показ экрана —
  только самому порталу, для звонков).
- Вход: блокировка учётной записи после 5 неудачных попыток на 15 минут и ограничение частоты
  запросов входа с одного адреса (`TEACHERBOX_SECURITY_AUTH_RATE_LIMIT_*`, по умолчанию
  30 в минуту). Адрес клиента берётся из `X-Forwarded-For`, поэтому публикуйте порт портала
  только через свой прокси.
- Журнал входов — логгер `teacherbox.audit`: строки `Sign-in succeeded/failed` с логином и адресом.

## Журналы

- `docker compose logs -f` — журнал в обычном текстовом виде; ротация — 5 файлов по 10 МБ.
- Тот же журнал в JSON (формат ECS) пишется в `/data/logs/teacher-box.log`; старые файлы
  сжимаются рядом (`teacher-box.log.<дата>.<n>.gz`). По умолчанию — файлы по 10 МБ, не больше
  100 МБ и 30 дней; меняется переменными `LOGGING_LOGBACK_ROLLINGPOLICY_MAX_FILE_SIZE`,
  `..._TOTAL_SIZE_CAP`, `..._MAX_HISTORY`. По этим файлам ищет раздел администратора.
- Для систем сбора логов включите JSON и в консоли: `LOGGING_STRUCTURED_FORMAT_CONSOLE=ecs`
  (или `logstash`, `gelf`).
- У каждого запроса есть код (`X-Request-Id`, поле `requestId` в журнале). Сообщение об ошибке
  сервера в интерфейсе показывает этот код — по нему администратор находит запрос в журнале.
  Ошибки браузера тоже попадают в журнал (логгер `ru.teacherbox.client`).
- Пароль учителя, сгенерированный при первом запуске, печатается один раз:
  `docker compose logs | grep "Teacher account"`.

## Администратор

Отдельная техническая учётная запись для того, кто помогает с сервером ([ADR-0010](adr/0010-administrator-and-diagnostics.md)).
Данных учеников (имён, оплат, работ, текстов сообщений) администратор не видит.

- Включение: задайте `TEACHERBOX_IDENTITY_ADMIN_PASSWORD` (не короче 8 символов) и, при
  желании, `TEACHERBOX_IDENTITY_ADMIN_LOGIN` (по умолчанию `admin`), перезапустите портал и
  войдите на обычной странице входа — откроется раздел `/admin`. Пароль потом можно сменить в
  «Моём аккаунте»; он сохраняется, пока администратор включён.
- Выключение: уберите `TEACHERBOX_IDENTITY_ADMIN_PASSWORD` и перезапустите портал — учётная
  запись отключится. При повторном включении действует пароль из переменной.
- Разделы:
  - «Журнал» — поиск по периоду, уровню, логгеру, тексту и коду запроса; временное включение
    подробного журнала (`DEBUG`) для части приложения — через заданное время уровень вернётся сам.
  - «Состояние» — версия, время работы, память, свободное место, размер базы и журналов,
    health-проверки.
  - «События» — доменные события, которые ещё не обработаны (например, уведомление не создано
    из-за сбоя), с повторной отправкой; неудачные доставки в мессенджеры с повтором.
  - «Интеграции» — проверка связи с ботами мессенджеров (через их прокси), провайдером ИИ (без
    расхода токенов) и Google Календарём; журнал запросов к ИИ (без текстов).
  - «Диагностика» — архив для разработчика: последние файлы журнала (до 20 МБ), настройки
    `TEACHERBOX_*` со скрытыми паролями, токенами и ключами, состояние и версии.
  - «Настройки» — все переменные `.env` по разделам: значение и откуда оно (по умолчанию, `.env`
    или задано здесь). Изменения подтверждаются паролем администратора, важнее `.env` и
    применяются после перезапуска портала (в Docker — сам, иначе вручную). Пароли, токены и
    ключи не показываются — их можно только задать заново. Переменные Docker (порт, версия,
    лимиты) и учётные записи учителя и администратора здесь только видны. Если после изменения
    портал не запускается, исправьте или удалите значение в `config/settings.properties` в
    папке данных и перезапустите контейнер.
- Действия администратора пишутся в журнал с логгером `teacherbox.audit`.

### Что отправлять разработчику

1. Код ошибки из сообщения, которое видел учитель или ученик, и примерное время.
2. Диагностический архив («Диагностика» → «Скачать архив»). Перед отправкой его можно
   открыть: в архиве нет данных учеников, но в журнале могут быть логины и идентификаторы.
3. Если ошибку нужно повторить — включите на время `DEBUG` для нужного раздела
   (например, `ru.teacherbox.notifications`), повторите действие и скачайте архив снова.

## Внешние интеграции и прокси

- Telegram и провайдер ИИ могут ходить через прокси (`TEACHERBOX_NOTIFICATIONS_TELEGRAM_PROXY`,
  `TEACHERBOX_AI_PROXY`; `http://` или `socks5://`, без пароля) — см. README, раздел «Прокси
  для Telegram и ИИ». Неверный адрес прокси останавливает запуск с сообщением о переменной.
- При старте в журнале видно, через какой прокси идут запросы:
  `Telegram is reached through the proxy socks5://...`.
- Связь с мессенджерами проверяется непрерывно (long polling): при сбое в журнале
  `Polling TELEGRAM failed, retrying in N s: <причина>`, после восстановления —
  `Receiving messages from TELEGRAM`. Текущее состояние — «Настройки» → «Интеграции».
- Типичные причины: прокси слушает только `127.0.0.1` (из контейнера не виден), VPN не
  подключён, неверный порт или тип прокси (`http` вместо `socks5`).

## Видеозвонки (LiveKit)

Встроенные звонки идут через медиасервер LiveKit — отдельный контейнер `livekit` в обоих
compose-файлах (профиль `calls`, ADR-0030). Без него портал работает как раньше — с внешними
ссылками на видеосвязь.

**Включение.**

1. Придумайте ключ и секрет API (секрет — не короче 32 символов), например:
   `openssl rand -hex 24`. Запишите в `.env`:
   ```
   TEACHERBOX_MEETINGS_LIVEKIT_API_KEY=teacherbox
   TEACHERBOX_MEETINGS_LIVEKIT_API_SECRET=<секрет>
   COMPOSE_PROFILES=calls
   ```
2. Откройте на сервере порты для медиа: **7881/tcp**, **7882/udp**, **3478/udp** (TURN) и
   **30000–30049/udp** (ретрансляция TURN). Порт 7880 наружу открывать не нужно.
3. `docker compose -f compose.split.yaml up -d` (или `compose.single.yaml`).

**Публичный адрес.** LiveKit сам узнаёт внешний IP сервера через STUN. Если сервер за NAT с
пробросом портов или у него несколько адресов, задайте адрес сами:
`TEACHERBOX_LIVEKIT_USE_EXTERNAL_IP=false` и `TEACHERBOX_LIVEKIT_NODE_IP=<внешний IP>`. Для проверки на
своём компьютере — `false` и `127.0.0.1`.

**Сигнализация через адрес портала.** Браузер подключается к `wss://<портал>/livekit`.

- Вариант split: nginx фронтенда уже передаёт `/livekit/` в контейнер `livekit`.
- Вариант single: своего nginx нет — добавьте правило в обратный прокси перед порталом
  (LiveKit слушает `127.0.0.1:7880`, порт меняет `TEACHERBOX_LIVEKIT_HTTP_PORT`). Caddy:
  ```
  handle_path /livekit/* {
      reverse_proxy 127.0.0.1:7880
  }
  ```
  nginx:
  ```
  location /livekit/ {
      proxy_pass http://127.0.0.1:7880/;
      proxy_http_version 1.1;
      proxy_set_header Upgrade $http_upgrade;
      proxy_set_header Connection "upgrade";
      proxy_read_timeout 1h;
  }
  ```
- Свой прокси перед вариантом split тоже должен пропускать WebSocket на `/livekit/`.

**LiveKit на другом сервере.** Браузер всегда подключается к `<адрес портала>/livekit`, поэтому
направьте этот путь на свой LiveKit: в варианте split — переменной `LIVEKIT_URL` контейнера
`frontend`, в варианте single — правилом своего прокси. Портал ходит к LiveKit по
`TEACHERBOX_MEETINGS_LIVEKIT_API_URL` (по умолчанию `http://livekit:7880`); ключ и секрет — те же.
Профиль `calls` тогда не нужен.

**Если нет видео или звука.** Проверьте, что открыты UDP-порты и верен публичный адрес (в журнале
LiveKit строка `starting LiveKit server` с `nodeIP`); в сетях, где UDP закрыт, звонок идёт через
TCP 7881 — качество может быть хуже. Состояние связи с LiveKit — «Настройки» → «Интеграции» у
администратора.

**Если звук заикается.** Прерывистый звук — почти всегда потери или задержки пакетов по дороге:

- *UDP закрыт, звонок идёт через TCP 7881.* Любая потеря в TCP задерживает весь поток — звук
  «замирает» и догоняет. Откройте 7882/udp (и 3478/udp, 30000–30049/udp) на сервере и в облачном
  файрволе.
- *Docker Desktop (Windows, macOS).* Его проброс UDP-портов теряет пакеты под нагрузкой — для звонков
  ставьте портал на Linux-сервер.
- *Слабый канал у участника.* Видео 720p берёт до 1,5–2 Мбит/с исходящего канала; при перегрузке
  страдает и звук. Помогает выключить камеру или подключиться по кабелю вместо Wi-Fi; на сервере —
  свободный канал (сотни килобит на каждого участника каждой комнаты).
- *Перегружен сервер или компьютер участника.* Смотрите загрузку CPU контейнера `livekit`
  (`docker stats`), при нехватке поднимите `TEACHERBOX_LIVEKIT_CPU_LIMIT`. На старом ноутбуке
  закройте лишние вкладки.
- *Bluetooth-гарнитура* при включённом микрофоне переходит в «телефонный» режим — звук хуже и может
  прерываться; проверьте с проводными наушниками.

Индикатор слабой связи (значок Wi-Fi у имени участника) показывает, у кого проблема.

## Ресурсы

- Лимиты контейнера: `TEACHERBOX_MEMORY_LIMIT` (по умолчанию 1 ГБ; JVM берёт 75%) и
  `TEACHERBOX_CPU_LIMIT` (по умолчанию 2); у LiveKit — `TEACHERBOX_LIVEKIT_MEMORY_LIMIT` (512 МБ) и
  `TEACHERBOX_LIVEKIT_CPU_LIMIT` (2). Для одного учителя с десятками учеников хватает
  512 МБ.
- Остановка — корректная (graceful shutdown до 20 с, база закрывается штатно).

## Обслуживание

Каждую ночь портал сам удаляет истёкшие refresh-токены, старые приглашения (старше 30 дней)
и журнал доставок в мессенджеры старше 90 дней. Уведомления в личном кабинете и журнал
запросов к ИИ сохраняются.
