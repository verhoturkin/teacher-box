# Эксплуатация Teacher Box

Документ для учителя или администратора, который развернул портал на своём сервере.
Все настройки — переменные окружения в файле `.env` (образец — [`.env.example`](../.env.example)).

## Данные

Всё состояние портала хранится в одном каталоге — `/data` в контейнере (Docker-том
`teacherbox-data`), `./backend/data` при локальном запуске:

| Путь | Что там |
|---|---|
| `db/` | база данных H2 |
| `files/` | вложения домашних заданий |
| `keys/` | ключ подписи токенов (если не задан `TEACHERBOX_SECURITY_JWT_SECRET`) |
| `backups/` | резервные копии |
| `restore/` | архив для восстановления при следующем запуске |

## Резервные копии

- Копия создаётся **каждую ночь** (`TEACHERBOX_BACKUP_CRON`, по умолчанию в 03:30 по времени
  `TEACHERBOX_TIMEZONE`), хранятся последние `TEACHERBOX_BACKUP_KEEP` копий (по умолчанию 7).
- Вручную: «Настройки» → «Резервные копии» → «Создать копию сейчас». Там же копии можно скачать.
- Архив `teacherbox-<дата>-<время>.zip` содержит `database.sql` (полный SQL-дамп базы,
  переносимый между версиями H2), каталог `files/` и `manifest.properties`.
- **Храните копии вне сервера**: скачивайте их или копируйте каталог `backups/` в облако —
  копия на том же диске не спасёт от его поломки.

Скопировать все копии с сервера:

```bash
docker compose -f compose.single.yaml cp app:/data/backups ./teacherbox-backups
```

### Восстановление

1. Положите архив в каталог `restore/` данных:
   ```bash
   docker compose -f compose.single.yaml cp teacherbox-20260925-033000-000.zip app:/data/restore/
   ```
2. Перезапустите портал: `docker compose -f compose.single.yaml restart`.
3. При старте, до открытия базы, портал:
   - переносит текущие `db/` и `files/` в `restore/previous-<время>/` (на случай отката);
   - восстанавливает базу из `database.sql` и файлы из `files/`;
   - переносит архив в `restore/applied/`.
4. Если восстановление не удалось, прежние данные возвращаются на место, портал не запускается,
   причина — в журнале (`docker compose logs`). Уберите архив из `restore/` и перезапустите.

Если в `restore/` несколько архивов, восстанавливается последний по имени (самый новый).

## Безопасность

- Портал рассчитан на работу **за HTTPS** (reverse proxy: Caddy, nginx, Traefik). Cookie сессии
  получает флаг `Secure`, когда прокси передаёт `X-Forwarded-Proto: https`.
- Заголовки: Content-Security-Policy (без inline-скриптов), `X-Frame-Options: DENY`,
  `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`.
- Вход: блокировка учётной записи после 5 неудачных попыток на 15 минут и ограничение частоты
  запросов входа с одного адреса (`TEACHERBOX_SECURITY_AUTH_RATE_LIMIT_*`, по умолчанию
  30 в минуту). Адрес клиента берётся из `X-Forwarded-For`, поэтому публикуйте порт портала
  только через свой прокси.
- Журнал входов — логгер `teacherbox.audit`: строки `Sign-in succeeded/failed` с логином и адресом.

## Журналы

- `docker compose logs -f` — журнал в обычном текстовом виде; ротация — 5 файлов по 10 МБ.
- Тот же журнал в JSON (формат ECS) пишется в `/data/logs/teacher-box.log`; старые файлы
  сжимаются рядом (`teacher-box.log.<дата>.<n>.gz`). По умолчанию — файлы по 10 МБ, не больше
  100 МБ и 30 дней; меняется переменными `LOGGING_LOGBACK_ROLLINGPOLICY_MAX_FILE_SIZE`,
  `..._TOTAL_SIZE_CAP`, `..._MAX_HISTORY`. По этим файлам ищет раздел администратора.
- Для систем сбора логов включите JSON и в консоли: `LOGGING_STRUCTURED_FORMAT_CONSOLE=ecs`
  (или `logstash`, `gelf`).
- У каждого запроса есть код (`X-Request-Id`, поле `requestId` в журнале). Сообщение об ошибке
  сервера в интерфейсе показывает этот код — по нему администратор находит запрос в журнале.
  Ошибки браузера тоже попадают в журнал (логгер `ru.teacherbox.client`).
- Пароль учителя, сгенерированный при первом запуске, печатается один раз:
  `docker compose logs | grep "Teacher account"`.

## Администратор

Отдельная техническая учётная запись для того, кто помогает с сервером ([ADR-0010](adr/0010-administrator-and-diagnostics.md)).
Данных учеников (имён, оплат, работ, текстов сообщений) администратор не видит.

- Включение: задайте `TEACHERBOX_IDENTITY_ADMIN_PASSWORD` (не короче 8 символов) и, при
  желании, `TEACHERBOX_IDENTITY_ADMIN_LOGIN` (по умолчанию `admin`), перезапустите портал и
  войдите на обычной странице входа — откроется раздел `/admin`. Пароль потом можно сменить в
  «Моём аккаунте»; он сохраняется, пока администратор включён.
- Выключение: уберите `TEACHERBOX_IDENTITY_ADMIN_PASSWORD` и перезапустите портал — учётная
  запись отключится. При повторном включении действует пароль из переменной.
- Разделы:
  - «Журнал» — поиск по периоду, уровню, логгеру, тексту и коду запроса; временное включение
    подробного журнала (`DEBUG`) для части приложения — через заданное время уровень вернётся сам.
  - «Состояние» — версия, время работы, память, свободное место, размер базы и журналов,
    health-проверки.
  - «События» — доменные события, которые ещё не обработаны (например, уведомление не создано
    из-за сбоя), с повторной отправкой; неудачные доставки в мессенджеры с повтором.
  - «Интеграции» — проверка связи с ботами мессенджеров (через их прокси), провайдером ИИ (без
    расхода токенов) и Google Календарём; журнал запросов к ИИ (без текстов).
  - «Диагностика» — архив для разработчика: последние файлы журнала (до 20 МБ), настройки
    `TEACHERBOX_*` со скрытыми паролями, токенами и ключами, состояние и версии.
- Действия администратора пишутся в журнал с логгером `teacherbox.audit`.

### Что отправлять разработчику

1. Код ошибки из сообщения, которое видел учитель или ученик, и примерное время.
2. Диагностический архив («Диагностика» → «Скачать архив»). Перед отправкой его можно
   открыть: в архиве нет данных учеников, но в журнале могут быть логины и идентификаторы.
3. Если ошибку нужно повторить — включите на время `DEBUG` для нужного раздела
   (например, `ru.teacherbox.notifications`), повторите действие и скачайте архив снова.

## Внешние интеграции и прокси

- Telegram и провайдер ИИ могут ходить через прокси (`TEACHERBOX_NOTIFICATIONS_TELEGRAM_PROXY`,
  `TEACHERBOX_AI_PROXY`; `http://` или `socks5://`, без пароля) — см. README, раздел «Прокси
  для Telegram и ИИ». Неверный адрес прокси останавливает запуск с сообщением о переменной.
- При старте в журнале видно, через какой прокси идут запросы:
  `Telegram is reached through the proxy socks5://...`.
- Связь с мессенджерами проверяется непрерывно (long polling): при сбое в журнале
  `Polling TELEGRAM failed, retrying in N s: <причина>`, после восстановления —
  `Receiving messages from TELEGRAM`. Текущее состояние — «Настройки» → «Интеграции».
- Типичные причины: прокси слушает только `127.0.0.1` (из контейнера не виден), VPN не
  подключён, неверный порт или тип прокси (`http` вместо `socks5`).

## Ресурсы

- Лимиты контейнера: `TEACHERBOX_MEMORY_LIMIT` (по умолчанию 1 ГБ; JVM берёт 75%) и
  `TEACHERBOX_CPU_LIMIT` (по умолчанию 2). Для одного учителя с десятками учеников хватает
  512 МБ.
- Остановка — корректная (graceful shutdown до 20 с, база закрывается штатно).

## Обслуживание

Каждую ночь портал сам удаляет истёкшие refresh-токены, старые приглашения (старше 30 дней)
и журнал доставок в мессенджеры старше 90 дней. Уведомления в личном кабинете и журнал
запросов к ИИ сохраняются.
