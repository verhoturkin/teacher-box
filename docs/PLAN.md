# План реализации Teacher Box

Пошаговый план. Каждый подэтап завершается зелёным `./scripts/verify.sh` и коммитом
(см. AGENTS.md §8–9). Отмечайте `[x]` в том же коммите, что и код.

Легенда: **B** — backend, **F** — frontend, **D** — docker/инфраструктура.

# Версия 1.1

Цели: расписание с напоминаниями и календарями, работа Telegram из РФ через прокси,
содержательные главные страницы, простой путь учителя в уведомлениях, Gemini, роль
администратора для отладки. Этапы идут в порядке зависимостей: прокси нужен Telegram, ИИ и
Google; главная страница собирается из виджетов расписания, оплат, заданий и уведомлений.

Новые решения: ADR-0008 (расписание и календари), ADR-0009 (настройки интеграций в БД и
исходящий прокси), ADR-0010 (администратор и диагностика); дополнения в ADR-0006 (Gemini)
и ADR-0007 (FullCalendar).

## Этап 11. Исходящий прокси для внешних интеграций

- [x] 11.1 **B** `shared.http.OutboundProxy`: разбор `http://[user:pass@]host:port` и
      `socks5://host:port`, фабрика HTTP-клиента для `RestClient` (JDK `HttpClient` не умеет
      SOCKS — с прокси используется `HttpURLConnection` + `java.net.Proxy`, HTTP/1.1),
      пароль прокси не попадает в логи. Тесты с локальными HTTP- и SOCKS5-прокси.
- [x] 11.2 **B** Telegram через `TEACHERBOX_NOTIFICATIONS_TELEGRAM_PROXY`: long polling и
      отправка; проверка связи (`getMe`) при старте — понятная ошибка в логе и статус в
      «Настройках». VK и MAX всегда ходят напрямую (российские сервисы).
- [x] 11.3 **B** ИИ через `TEACHERBOX_AI_PROXY`: Anthropic SDK (`proxy` + `proxyAuthenticator`)
      и OpenAI-совместимые провайдеры — API Anthropic, OpenAI и Gemini из РФ недоступны.
- [x] 11.4 **D** `extra_hosts: host.docker.internal:host-gateway` в compose; документация:
      прокси на хосте, прокси в соседнем контейнере (xray/sing-box с входом SOCKS5/HTTP),

      VPS). `.env.example`, README, `docs/operations.md`.

## Этап 12. ИИ: Gemini

Итог исследования: **подписку Google AI Pro подключить нельзя.** Её преимущества действуют
только в веб-интерфейсе Google AI Studio; вызовы Gemini API из приложений оплачиваются
отдельно; использование OAuth-токенов Gemini CLI сторонними программами нарушает условия
Google (с февраля 2026 — блокировка аккаунтов, в том числе платных). Официального способа
для сторонних приложений нет. Законный путь — ключ Gemini API из Google AI Studio
(бесплатный уровень с лимитами или оплата по токенам).

- [x] 12.1 **B** Провайдер `gemini`: пресет OpenAI-совместимого адаптера
      (`https://generativelanguage.googleapis.com/v1beta/openai/`, модель по умолчанию —
      `gemini-3.8-flash`), проверка structured outputs на схемах черновиков и причин отказа
      (safety → `ai.refused`); если совместимый endpoint не справляется со схемами — отдельный
      адаптер на официальном Java SDK `google-genai`. Тесты на локальном HTTP-сервере.
- [x] 12.2 **F/D** Провайдер и модель на странице «ИИ»; README: получение ключа, недоступность
      в РФ (→ `TEACHERBOX_AI_PROXY`), лимиты бесплатного уровня и то, что на бесплатном уровне
      Google может использовать тексты запросов (ответы учеников) для улучшения своих продуктов.

## Этап 13. Модуль расписания (`schedule`) — backend

- [x] 13.1 **B** ADR-0008, модуль `schedule` (зависит от `shared`, `identity::api`), схема
      `schedule`: `series`, `lessons`, `change_requests`, `feeds`; таблица зависимостей в
      AGENTS.md (`billing` и `notifications` получают `schedule::api` — только события).
- [x] 13.2 **B** Домен: занятие (ученик, начало, длительность, тема, ссылка на онлайн-урок;

      создаются на 12 недель вперёд и продлеваются ночью, изменение серии «с этой даты»,
      предупреждение о пересечении занятий.
- [x] 13.3 **B** Перенос и отмена: учитель — сразу; ученик — запрос (перенос на предложенное

- [x] 13.4 **B** Итог занятия «Проведено» / «Пропуск» → событие → `billing` записывает занятие

- [x] 13.5 **B** События `LessonScheduled`, `LessonRescheduled`, `ScheduledLessonCancelled`,
      `LessonCompleted`, `ChangeRequested`, `ChangeRequestResolved`; напоминания
      `LessonStartingSoon` за интервалы `TEACHERBOX_SCHEDULE_REMINDERS` (по умолчанию
      `PT24H,PT1H`), по одному на интервал.
- [x] 13.6 **B** REST: `/api/teacher/schedule/**` (занятия за период, занятия и серии,
      итоги, запросы), `/api/me/schedule/**` (свои занятия, запросы); тесты «чужой ученик →

- [x] 13.7 **B** Подписка на календарь (ICS, RFC 5545) по секретной ссылке

- [x] 14.4 E2E: занятие → запрос переноса → подтверждение → «Проведено» → баланс ученика.

## Этап 15. Google Календарь учителя

- [x] 15.1 **B** Подключение через OAuth 2.0 (кнопка «Подключить Google»): OAuth-клиент типа
      «веб-приложение» в Google Cloud учителя, client id/secret задаются в интерфейсе или в
      переменных окружения; redirect `<адрес портала>/api/public/schedule/google/callback`
      (адрес, по которому открыт портал; нужен HTTPS, без него — однократное подключение через
      `http://localhost` по SSH-туннелю), `state` против CSRF, refresh-токен хранится в БД, отзыв при отключении.
      Минимальный scope `calendar.app.created`: Teacher Box создаёт свой календарь
      «Teacher Box» и управляет событиями только в нём.
- [x] 15.2 **B** Односторонняя синхронизация Teacher Box → Google: outbox (создание / изменение
      / удаление событий, повторы, 404/410, истёкший или отозванный токен → статус «нужно
      переподключить» и уведомление учителю), `RestClient` + `MockRestServiceServer`,
      прокси `TEACHERBOX_SCHEDULE_GOOGLE_PROXY`.
- [x] 15.3 **B** Проверка занятости (по желанию, дополнительный scope `calendar.freebusy`):
      при планировании — предупреждение о пересечении с личными событиями учителя.
- [x] 15.4 **F** «Настройки» → «Google Календарь»: пошаговая инструкция с адресом для
      redirect, ввод client id/secret, «Подключить» / «Отключить», статус и ошибки
      синхронизации.
- [x] 15.5 **D** README: проект в Google Cloud, Calendar API, экран согласия (перевод в

## Этап 16. Уведомления: простой путь учителя

Что мешает сейчас: боты настраиваются только переменными окружения и перезапуском; раздела
уведомлений нет в меню учителя; не видно, кто из учеников подключил мессенджер; нельзя
выбрать, о чём уведомлять; неудачные доставки показаны на другой странице.

- [x] 16.1 **B** ADR-0009. Настройки каналов в БД: токены ботов задаются в интерфейсе
      (переменные окружения по-прежнему работают и имеют приоритет), проверка токена
      (`getMe` / `groups.getById` / `/me`), перезапуск адаптера и long polling без перезапуска
      приложения. Токены не отдаются в браузер.
- [x] 16.2 **B** Предпочтения получателя: какие типы уведомлений дублировать в мессенджеры
      (в личном кабинете — всегда), «тихие часы» (доставка откладывается до утра). Для
      учителя — статус подключения мессенджеров по ученикам и история рассылок.
- [x] 16.3 **F** Пункт «Уведомления» в меню учителя, вкладки: «Входящие», «Сообщения
      ученикам» (рассылка и история), «Мессенджеры» (мастер: создать бота по инструкции →
      вставить токен и проверить → подключить свой аккаунт кнопкой → тестовое сообщение),
      «Ученики» (кто что подключил, проблемы доставки, «Напомнить подключить»), «Что
      присылать».
- [x] 16.4 **F** Ученик: предложение подключить мессенджер после принятия приглашения и на
      главной; выбор, что присылать.

## Этап 17. Главная страница

## Этап 18. Администратор и диагностика

- [x] 18.1 **B** ADR-0010. Роль `ADMIN`: одна учётная запись из
      `TEACHERBOX_IDENTITY_ADMIN_LOGIN/PASSWORD` (пароль не задан — администратора нет);
      доступны только `/api/admin/**` и смена своего пароля. Администратор не видит данные
      учеников (имена, оплаты, работы) — только технические данные и идентификаторы. Его
      действия пишутся в аудит.
- [x] 18.2 **B** Журнал: файлы в `/data/logs` (JSON, ротация по размеру), идентификатор
      запроса (`X-Request-Id`, MDC, поле в ProblemDetail — «код ошибки», который учитель
      может назвать администратору), ошибки браузера отправляются на сервер
      (`/api/client-errors`, ограничение частоты).
- [x] 18.3 **B** `/api/admin/**`: поиск по журналу (период, уровень, логгер, текст, код
      запроса); смена уровня логирования на лету с автоматическим возвратом; состояние
      (версия, время работы, память, диск, размер БД, health); незавершённые события
      Modulith (просмотр, повторная отправка); неудачные доставки (повтор); журнал запросов к
      ИИ (без текстов); проверка связи с интеграциями (Telegram через прокси, ИИ, Google);
      диагностический архив для разработчика (журнал, настройки без секретов, версии).
- [x] 18.4 **F** Область `/admin/**`: «Журнал», «Состояние», «События», «Интеграции»,
      «Диагностика». Код ошибки в сообщениях об ошибках у учителя и ученика.
- [x] 18.5 **D** `docs/operations.md`: включение администратора, работа с журналом, что
      отправлять разработчику.
