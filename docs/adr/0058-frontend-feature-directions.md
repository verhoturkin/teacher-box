# ADR-0058: Направления зависимостей между фичами фронтенда

Дата: 2026-11-10. Статус: принято.

## Контекст

У модулей бэкенда есть таблица разрешённых зависимостей (`AGENTS.md` §4.2), и её проверяют
тесты. У фронтенда правило проверяло только способ импорта: чужая фича — через
`@features/<name>` или `@features/<name>/parts`. Направление не проверял никто, а
`scripts/import-cycles.mjs` ловил только циклы между файлами.

Граф на момент решения (импорты не-тестовых файлов, включая `import type`):

| Фича | Импортирует |
|---|---|
| `help`, `meetings` | — |
| `ai`, `boards` | `identity` |
| `notifications` | `help`, `identity` |
| `textbooks` | `boards`, `identity` |
| `billing` | `help`, `identity`, `notifications` |
| `homework` | `ai`, `boards`, `help`, `identity`, `schedule`, `textbooks` |
| `schedule` | `ai`, `boards`, `help`, `homework`, `identity`, `meetings` |
| `identity` | `billing`, `help`, `homework`, `meetings`, `notifications`, `schedule` |
| `materials` | `boards`, `help`, `identity`, `textbooks` |
| `admin` | `help`, `settings` |
| `home`, `settings` | `help` и бизнес-фичи |

Циклов два. `identity` — основа, которую импортируют почти все, — сама собирала экран
«Ученики» и «Мой аккаунт» из карточек `billing`, `homework`, `meetings`, `notifications`,
`schedule`; цикл между файлами не замыкался только потому, что страницы лежат в `index.ts`, а
не в `parts.ts`. `homework` и `schedule` читали данные друг друга: редактор задания — уроки для
срока «к следующему уроку», итог урока — названия заданий.

## Решение

- **Три слоя, одна таблица.** Таблица живёт в `frontend/eslint.config.js` и повторена в
  `frontend/AGENTS.md`.
  - Основа: `help` не импортирует ничего, `identity` — только `help`.
  - Бизнес-фичи импортируют основу и перечисленные для них бизнес-фичи: `textbooks` → `boards`;
    `billing` → `notifications`; `homework` → `ai`, `boards`, `textbooks`; `schedule` → `ai`,
    `boards`, `homework`, `meetings`. У `ai`, `boards`, `meetings`, `notifications` — только
    основа.
  - Сборочные фичи (`account`, `admin`, `home`, `materials`, `settings`, `students`, а с этапа
    371 — `gallery`) импортируют основу и любые бизнес-фичи. Их самих не импортирует никто;
    единственное исключение — `admin` → `settings` (карточка резервных копий).
- **Таблица — не копия бэкенда.** На бэкенде стрелка идёт от потребителя события или данных к
  их владельцу (`notifications` → `billing`, `ai` → `homework`). На фронтенде зависит тот, кто
  встраивает чужой виджет в свой экран: `billing` открывает диалог рассылки `notifications`,
  `homework` и `schedule` встраивают кнопки `ai`. Поэтому направления записаны по фактическому
  встраиванию, а совпадать с бэкендом обязаны только границы фич.
- **Проверки.** ESLint `no-restricted-imports` запрещает импорт фичи, которой нет в строке
  таблицы, — и в тестах тоже, и для `import type`. Фича без строки в таблице — ошибка
  конфигурации. `scripts/import-cycles.mjs` дополнительно падает на цикле между фичами: это
  страховка от стрелки, добавленной в таблицу по ошибке.
- **Корень приложения** (`app.routes.ts`, `app.config.ts`, `search-sources.ts`) стоит над
  фичами: он лениво подключает любую из них и передаёт странице то, что она сама взять не
  вправе.
- **Экран «Ученики» — сборочная фича `students`.** В неё уходят `identity/students/` и
  `identity/groups/` целиком, кроме выбора получателей (`member-picker`, `member-recipients`):
  страница, карточки ученика и группы, их вкладки, диалоги ученика, группы и приглашения — со
  своими ключами словаря. В `identity` остаются вход, приглашение, аккаунт, API справочника,
  цвета, выбор получателей и теги.
- **«Мой аккаунт».** `AccountPanel` остаётся в `identity` и получает раздел уведомлений через
  именованный слот-шаблон (`tbAccountNotifications`), а не импортом. Страница ученика и
  администратора переезжает в сборочную фичу `account`, учитель заполняет слот в `settings`.
  План предлагал перенести страницу в `settings`; отказались, потому что тогда ученик, открыв
  аккаунт, загружал бы весь чанк настроек учителя.
- **`homework` ↔ `schedule`.** Остаётся `schedule` → `homework`: итог урока читает задания.
  Редактор задания объявляет, что ему нужно (`UpcomingLessons` — функция, читающая уроки за
  период), и получает это входом из маршрута; маршрут в корне приложения лениво берёт
  `ScheduleApi`. Порт в `core/` не заводили: он нужен одной странице, а `core/` не должен знать
  об уроках. Токен DI не подошёл: его пришлось бы статически импортировать в корне, и части
  `homework` попали бы в первый бандл.

## Последствия

- Для пользователя ничего не меняется: адреса, разметка, тексты и поведение те же. Чанк входа
  становится меньше — в нём больше нет экрана «Ученики».
- Новая фича получает строку в таблице; новая стрелка — правка таблицы и `frontend/AGENTS.md` в
  одном коммите, и она не должна замыкать цикл.
- Если бизнес-фиче нужны данные фичи, которая стоит выше, она объявляет вход, а данные передаёт
  маршрут или сборочная фича. Встраивать экран снизу вверх нельзя.
- Правило вводится со списком известных нарушений (`PENDING_DIRECTIONS`), который пустеет на
  этапах 370.2–370.3 и удаляется.
