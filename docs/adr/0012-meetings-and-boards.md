# ADR-0012. Видеовстречи (Яндекс Телемост) и доски (Холст)

- Статус: принято; часть «Доски» заменена [ADR-0028](0028-excalidraw-boards.md), часть «Телемост» — [ADR-0030](0030-livekit-calls.md)
- Дата: 2026-09-27

## Контекст

Учитель проводит уроки в Яндекс Телемосте и работает с учениками на интерактивной доске Холст
(app.holst.so). Нужно: создавать встречи и раздавать ссылки ученикам, открывать встречу у учителя
в приложении Телемоста на компьютере, связывать доски с учениками и переносить на доски задания
и результаты ИИ.

Что умеют сервисы (исследование сентября 2026):

- **Телемост.** REST API `https://cloud-api.yandex.net/v1/telemost-api` с OAuth-токеном Яндекс ID
  (права `telemost-api:conferences.create/read/update`). По описанию API обычную публичную встречу
  может создать и пользователь с личным Яндекс ID, трансляции и доступ «только для организации» —
  пользователи Яндекс 360 для бизнеса. Приложение Телемоста для компьютера открывается ссылкой
  `telemost://<адрес встречи>` (так его открывает сам веб-клиент; схема не документирована).
- **Холст.** Публичный API (персональные токены) даёт только чтение журнала аудита организаций.
  Доски умеет менять только локальный MCP-сервер приложения Холст для ПК (`127.0.0.1:47641`,
  бета) — с сервера портала он недоступен, а из браузера — только на компьютере учителя с
  запущенным приложением.

## Решение

### Видеовстречи — модуль `meetings`

- Модуль `meetings` (зависит от `shared`, `identity::api`), своя схема: комнаты, подключение
  Яндекса, начатые авторизации.
- **Постоянная комната** у каждого ученика и у каждой группы: одна ссылка на всё время. В отдельном
  занятии своя ссылка по-прежнему важнее комнаты. `schedule` получает `meetings::api` (фасад
  `MeetingRooms`, только чтение) и отдаёт в занятиях `joinUrl` — ссылку занятия или комнаты — в
  карточках, напоминаниях, календарях ICS и Google.
- **Два режима.** С подключённым Яндексом комната создаётся кнопкой через API (`POST /conferences`,
  зал ожидания — настройка учителя: `PUBLIC` или `ADMINS`). Без подключения учитель вставляет
  ссылку сам (Телемост или любая другая видеосвязь по https).
- **Подключение Яндекса** — OAuth 2.0 authorization code, как у Google Календаря (ADR-0008): приложение
  в Яндекс ID учителя, client id/secret в интерфейсе или в `TEACHERBOX_MEETINGS_YANDEX_CLIENT_ID/SECRET`,
  redirect `<адрес портала>/api/public/meetings/yandex/callback`, одноразовый `state`. Токен
  выдаётся для «устройства» (`device_id`), поэтому его можно отозвать при отключении. Для проверки
  и E2E можно задать готовый токен `TEACHERBOX_MEETINGS_TELEMOST_TOKEN` (он важнее подключения).
  Прокси не нужен: сервисы Яндекса доступны из РФ.
- **Отправка ссылки** — событие `MeetingLinkShared` (`meetings::api`) → `notifications` (ЛК и
  мессенджеры; зависимость на `meetings::api` — только события).
- **Открытие у учителя.** Кнопка «Начать урок» открывает ссылку Телемоста в приложении
  (`telemost://…`) — по умолчанию на Windows, настройка хранится на устройстве; рядом всегда есть
  «Открыть в браузере». Ученику — обычная ссылка (браузер или мобильное приложение).
- Проверка связи в разделе администратора: запрос несуществующей встречи — `404` значит, что
  токен принят, `401/403` — что нужно переподключить Яндекс.

### Доски — модуль `boards`

- Модуль `boards` (зависит от `shared`, `identity::api`): доски ученика и группы по ссылкам
  (ссылки Холста распознаются, допустима любая https-ссылка на доску).
- **Материалы на доску — через буфер обмена.** Для задания и результата ИИ интерфейс копирует
  форматированный текст и картинку и открывает доску; учитель вставляет их на доске. Автоматизация
  досок откладывается до появления у Холста серверного API.

## Последствия

- Схема `telemost://` не документирована и может измениться — поэтому у «Начать урок» всегда есть
  запасной вариант «Открыть в браузере», а приложение открывается только по настройке.
- Ссылка постоянной комнаты — секрет ученика: её знает каждый, кому её переслали. При утечке
  учитель пересоздаёт комнату.
- Интеграция с Холстом ограничена ссылками и копированием; при появлении API досок достаточно
  добавить адаптер в `boards`.
