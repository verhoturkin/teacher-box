# ADR-0050. Единая модель диалогов

- Статус: принято
- Действующие правила: [docs/design-system.md](../design-system.md) — сводка решений; при расхождении верна она
- Дата: 2026-10-26
- Изменяет: [ADR-0015](0015-design-system-and-mobile.md) (полноэкранные окна на телефоне),
  [ADR-0024](0024-accessibility.md) (модальный лист: начальный фокус),
  [ADR-0026](0026-decision-buttons-and-dialogs.md) (ширины окон, `tb-dialog--short`, окно занятия, начальный фокус, «окно не открывает второе»)
- Основание: [аудит диалогов 2026-10](../archive/audit/dialogs-2026-10.md)

## Контекст

Аудит 0.33.x нашёл **28 `p-dialog`**, **7 `p-drawer`** (один — навигация) и **12 хостов
подтверждений** (`<p-confirmdialog>` с `ConfirmationService`, объявленным локально в 9 компонентах).

- Общего компонента диалога нет: каждый из 28 сам задаёт атрибуты, футер, сброс при открытии,
  ожидание и ошибки (~30–40 строк на диалог), правила §8 соблюдаются выборочно.
- Вариант на телефоне выбирается «от противного»: всё, что не `tb-dialog--short`, — полноэкранное,
  включая просмотр и списки без полей ввода. Ширина и поведение на телефоне смешаны в одном классе.
- Полноэкранный вид не по M3: шапка PrimeNG с «✕» в конце и растянутые кнопки внизу.
- Один объект открывается разными контейнерами: урок учителя — диалог, урок ученика — нижний лист.
- В футере больше двух действий (`lesson-details-dialog`, `to-board-dialog`, `system-prompts`),
  у `request-answer-dialog` нет нейтрального выхода; «✕» и «Отмена» закрывают окно дважды.
- Начальный фокус на заголовке сделан в 4 из 28 окон.
- Подтверждение внутри окна — три самодельных шага (`board-backups`, `lesson-details`,
  `restore-dialog`); закрытие формы с изменениями молча теряет данные.
- Поля: по умолчанию outlined, filled — только в двух формах; варианты смешаны между разделами.
- `tb-button-group` оформлена как connected group, но используется для действий.

## Решение

### Три вида; вид выбирает содержание, а не экран

| Вид | Для чего | Compact (< 600 dp) | Medium и шире |
|---|---|---|---|
| `alert` | подтверждения, одно решение, ≤ 1 поля | basic dialog | basic dialog |
| `form` | ≥ 2 полей, мастера, выбор из списка | полноэкранный диалог M3 | basic dialog |
| `sheet` | объект и его действия | modal bottom sheet | basic dialog |

Содержимое и разметка диалога одни на всех ширинах, меняется только контейнер. Боковые листы
(справка, колокольчик, ИИ, проверка) остаются отдельным семейством и не меняются.

### Правила

- **Из M3:** basic dialog — 280–560 dp, углы 28 dp, отступы 24 dp, заголовок → текст 16 dp, текст →
  кнопки 24 dp, между кнопками 8 dp, surface container high, не больше двух действий.
  Полноэкранный — только compact: шапка 56 dp, «✕» первым, подтверждающая текстовая кнопка с ясным
  глаголом в конце шапки, не `disabled`; закрытие с изменениями — basic dialog поверх.
  Bottom sheet — углы 28 dp сверху, surface container low.
- **Наше решение:** bottom sheet только на compact (M3 допускает и medium); не больше двух
  действий в футере (подтвердить + отклонить), лишние и опасные — в «⋮» шапки; «✕» в `alert` и
  `form` с medium нет (Отмена, Esc), у `sheet` «✕» остаётся; скрим закрывает `alert` и `sheet`,
  `form` — никогда.
- **Начальный фокус** (наше решение): `form` — первое поле (так велит M3); `alert` и `sheet` —
  заголовок, чтобы Enter не подтвердил опасное действие.
- **Грязная форма** при закрытии спрашивает «Отменить изменения?» (Esc = Отмена). Диалог поверх
  диалога — только basic dialog поверх полноэкранного `form` на compact; в остальных случаях —
  встроенный шаг подтверждения.
- **Ошибки:** ошибка сервера в `form` — над формой; ошибка действия в `sheet` — snackbar.
- `request-answer`: один выбор «Одобрить | Отклонить» (connected, single-select) и одна кнопка.
- **Поля:** M3 filled text field везде; исключение — строка поиска (отдельный компонент M3).
  Контраст на surface container high проверяется в обеих темах; при нехватке — линия 1 dp
  on surface, роли M3 не меняются.
- **Карточка урока** — `sheet`: заголовок — с кем урок; один `tb-list` фактов; «Итог»
  («Проведено | Пропуск», connected, single-select, выбор необязателен); отмена урока — отдельный
  `form`; удаление — `Confirm` с выбором области серии.
- **Группы кнопок:** `tb-button-group--connected` (2 dp) — только переключатели;
  `tb-button-group` — стандартная группа M3 для действий (промежуток 12 dp, Compose
  `ButtonGroupSmall.BetweenSpace`).

### Общий код (`shared/ui`)

- `<tb-dialog>` — единственная обёртка над `p-dialog` / `p-drawer`: вид, ширина `normal | wide`,
  контейнер по ширине окна, шапка, футер, фокус и его возврат (из `ModalDrawer`), запрет закрытия,
  вопрос о несохранённых изменениях.
- `dialogSubmit()` — ожидание, ошибка, сброс при открытии, запрос, закрытие.
- `Confirm` — сервис `danger()` / `safe()` → `Promise<boolean>` поверх одного `<p-confirmdialog>`
  в `app.ts` и одного `ConfirmationService`; заменяет 9 провайдеров и 12 хостов.
- `<tb-dialog-confirm-step>` — встроенный шаг подтверждения вместо трёх самодельных.

## Последствия

- Минус ~500–700 строк шаблонов и классов, одно место правки поведения.
- Старые правила `.p-dialog:not(.p-confirmdialog, .tb-dialog--short)` и класс `tb-dialog--short`
  удаляются; ширины — параметр `width`, а не классы.
- Переход выполняется в 0.34.0 (этапы 285–288): общий код, затем поля, затем диалоги модулей.
- Изменённые ADR помечены «изменён ADR-0050»; действуют правила `docs/design-system.md` §8, §9, §11.
