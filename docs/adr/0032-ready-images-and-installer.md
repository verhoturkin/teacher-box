# ADR-0032. Готовые образы, установщик и HTTPS в комплекте

- Статус: принято
- Дата: 2026-10-06
- Дополняет: [ADR-0031](0031-split-variant-only.md) (вариант split остаётся единственным)
- Действующие правила: README («Установка», «Обновление», «HTTPS»), [docs/operations.md](../operations.md)

## Контекст

До 0.9.0 установка выглядела так: клонировать репозиторий, вручную заполнить `.env`, собрать образы на сервере
(`up --build` — Node и Maven внутри Docker, несколько минут и больше 1 ГБ памяти, на маленьком VPS сборка падала)
и отдельно поставить Caddy для HTTPS. Для звонков нужно было придумать ключ и секрет LiveKit, открыть порты, а
конфигурация LiveKit лежала в репозитории (`docker/livekit/livekit.yaml`), поэтому без клона не обойтись.
Обновление — `git pull` и новая сборка.

## Решение

- **Готовые образы.** CI на тег `v*` после всех проверок публикует `ghcr.io/verhoturkin/teacher-box-backend` и
  `-frontend` для `linux/amd64` и `linux/arm64` с тегами `X.Y.Z`, `X.Y` и `latest`. Сборочные стадии
  `docker/Dockerfile` идут на платформе сборщика (`$BUILDPLATFORM`): jar и SPA от архитектуры не зависят, под
  каждую платформу собираются только итоговые образы — без медленной эмуляции Maven и Node.
- **`compose.yaml`** (бывший `compose.split.yaml`) ссылается на образы GHCR и не требует файлов репозитория:
  конфигурация LiveKit встроена в переменную `LIVEKIT_CONFIG`. Сборка из исходников — переопределение
  `compose.build.yaml` (разработка, E2E, проверка в CI). Имя проекта и том данных прежние.
- **HTTPS в комплекте.** Необязательный контейнер `caddy` (профиль `https`) — `caddy reverse-proxy` с адресом
  из `TEACHERBOX_DOMAIN` — сам получает и продлевает сертификат Let's Encrypt; свой прокси по-прежнему можно
  поставить вместо него.
- **Установщик** `scripts/install.sh` (запуск `curl … | sudo bash`) проверяет Docker, задаёт несколько вопросов,
  генерирует ключ LiveKit, пишет `.env`, скачивает `compose.yaml` в `/opt/teacher-box`, запускает портал и
  печатает адрес, логин и пароль (его по-прежнему создаёт портал — так мастер первого входа попросит его
  сменить). `ufw` установщик не трогает: порты, опубликованные Docker, идут в обход него, поэтому он лишь
  перечисляет порты для файрвола провайдера. Команда `teacherbox` обслуживает установку: обновление (свежий
  `compose.yaml` + `pull`), журналы, состояние, копии, правка настроек.
- **Минимум настроек.** В `.env.example` сверху короткий блок «Main», всё остальное закомментировано со
  значениями по умолчанию; `TEACHERBOX_PUBLIC_URL` по умолчанию выводится из `TEACHERBOX_DOMAIN`.

## Последствия

- Установка — одна команда и несколько ответов, обновление — `teacherbox update` (или `pull` + `up -d`);
  сервер не держит исходники и не собирает образы, хватает ~1 ГБ памяти и на ARM-машинах.
- Выпуск зависит от GHCR и GitHub Actions; пакеты GHCR должны быть публичными (настраивается один раз).
- `latest` — последний выпуск: кому нужна фиксированная версия, задаёт `TEACHERBOX_VERSION`.
- Переход с `compose.split.yaml`: `git pull` и `docker compose up -d --remove-orphans` — данные остаются.
