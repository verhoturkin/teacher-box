# ADR-0013. Диалоги с ботами мессенджеров

- Статус: принято
- Дата: 2026-09-27

## Контекст

До версии 0.2 боты Telegram, ВКонтакте и MAX только присылали уведомления и принимали код
подключения. Версия 0.2 добавляет действия через бота: ученик смотрит расписание и оплаты,
просит отменить или перенести занятие; учитель отмечает занятия, записывает оплаты и отвечает на
запросы. Действия затрагивают данные разных модулей (`schedule`, `billing`, `meetings`, `boards`),
а мессенджеры живут в `notifications`, который по правилам изоляции (AGENTS.md §4.2) получает от
модулей только события.

Ограничения мессенджеров:

- **Telegram** — inline-клавиатура; нажатие приходит как `callback_query`, данные кнопки —
  до 64 байт, нажатие нужно подтвердить `answerCallbackQuery`; меню команд — `setMyCommands`.
- **ВКонтакте** — inline-клавиатура до 10 кнопок (до 5 в ряду), текстовая кнопка отправляет
  сообщение с `payload` (JSON до 255 символов) в `message_new`; кнопки работают, только если в
  сообществе включены «Возможности ботов» (иначе ошибка 912).
- **MAX** — `inline_keyboard` с кнопками `callback` и `link`; нажатие — `message_callback`,
  ответ — `POST /answers`.

## Решение

1. **SPI `shared.chat`.** Модуль, который умеет что-то делать через бота, объявляет бин
   `ChatAction`: id, пункт меню, для кого доступно, шаги диалога (`start`, `next`), а также
   кнопки под уведомлениями (`offer` по `ChatSubject`). Ответ — `ChatStep`: `Ask` (ждём
   следующий ввод, с состоянием `ChatState`) или `Done` (диалог окончен; для изменений —
   описание для аудита). В `shared.chat` — помощники: подтверждение, страницы кнопок, выбор с
   поиском по имени (`ChatPicker`), даты кнопками, время и суммы текстом. Как и
   `IntegrationCheck`, `notifications` собирает действия из контекста и не знает модулей;
   новых зависимостей между модулями нет. Действие проверяет права, как REST (ученик — только
   свои данные), и меняет только данные своего модуля через его сервисы.
2. **Движок в `notifications`** (`ChatEngine`):
   - работает только с подключёнными аккаунтами; роль — из `identity` (учитель или текущий
     ученик), к одному чату может быть подключено несколько учеников (родитель) — бот спрашивает,
     от чьего имени действовать;
   - главное меню по роли (`/menu`), «Отмена» на каждом шаге (`/cancel`), `/help`;
   - состояние диалога — в таблице `chat_dialogs` (истекает через 30 минут без ответа);
   - кнопки несут только `<токен>:<номер>` (12 + 3 байта); значение кнопки, действие и
     состояние диалога лежат в `chat_buttons`. Нажатие забирает весь набор кнопок сообщения —
     изменение нельзя подтвердить дважды; старая кнопка отвечает «уже не действует»;
   - уведомление может нести кнопки действия (колонка `keyboard` в очереди доставки), например
     «Принять» под запросом на перенос;
   - транзакции — у действий: отказ действия не откатывает состояние диалога;
   - изменения учителя пишутся в аудит (`AuditLog.bot`) без персональных данных;
   - учитель может выключить управление через бота (`chat_settings`) — уведомления продолжают
     приходить.
3. **Адаптеры** отправляют сообщения с кнопками и принимают нажатия в тех же циклах long polling.
   ВКонтакте без «Возможностей ботов» получает сообщения без кнопок (адаптер повторяет отправку
   без клавиатуры и пишет предупреждение в журнал).

## Последствия

- Новое действие бота — бин `ChatAction` в своём модуле и тесты; `notifications` не меняется.
- Кнопки под уведомлениями привязаны к типу `ChatSubject` — строке, о которой договариваются
  модуль-источник уведомления и модуль действия.
- Лимиты клавиатур (10 кнопок, 5 в ряду) обязательны для действий: движок обрезает лишнее.
- Сообщения бота — простой текст без разметки: одинаково во всех мессенджерах.
