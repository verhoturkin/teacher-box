# ADR-0016. Настройки портала в интерфейсе администратора

- Статус: принято
- Дата: 2026-09-28

## Контекст

До версии 1.5 почти все настройки портала (58 переменных `.env.example`) менялись только в файле
`.env` на сервере с перезапуском контейнера. Администратор (ADR-0010) видел часть из них в
диагностическом архиве, но не мог поменять: чтобы подключить бота, сменить прокси или
расписание копий, нужен был доступ к серверу.

Часть переменных нужна до того, как открывается база данных (адрес, часовой пояс, настройки
журнала, JWT), и все они читаются Spring Boot при запуске как свойства `teacherbox.*`.

## Решение

- Раздел «Настройки» у администратора (`/admin/settings`, `GET/PUT /api/admin/settings`)
  показывает все переменные `.env.example` по разделам: значение, откуда оно (по умолчанию,
  `.env`, задано здесь), пояснение. Каталог — `platform.settings.SettingsCatalog`; тест
  проверяет, что он совпадает с `.env.example`.
- Значения из интерфейса хранятся в файле `<data-dir>/config/settings.properties` (имена
  переменных как ключи), а не в базе: часть нужна до её открытия. Файл не входит в резервные
  копии — восстановление копии не меняет настроек сервера.
- При запуске `AdminSettingsLoader` (слушатель `ApplicationEnvironmentPreparedEvent`, после
  чтения конфигурации и до настройки журнала) кладёт значения файла первым источником свойств
  с правилами имён переменных окружения. Поэтому значение из интерфейса важнее `.env`, а
  «Вернуть как в .env» удаляет его из файла.
- Изменение подтверждается паролем администратора, каждое значение проверяется по типу
  (число, длительность, размер, cron, адрес, прокси, часовой пояс, валюта, выбор из списка), в
  журнал аудита пишутся только имена изменённых переменных. Затем портал перезапускается так
  же, как при восстановлении копии (`TEACHERBOX_BACKUP_RESTART`); без Docker — «перезапустите
  вручную».
- Секреты (пароли, токены, ключи, секрет JWT) не показываются: только «задан / не задан», их
  можно задать заново.
- Только для чтения:
  - переменные Docker Compose (порт, версия образа, лимиты памяти и процессора, параметры Java) —
    их читает Docker до запуска портала;
  - учётные записи учителя и администратора (логины, пароли, сброс пароля учителя): иначе
    администратор мог бы получить учётную запись учителя, а с ней данные учеников (ADR-0010),
    или закрыть себе вход. Учётные записи меняются в «Моём аккаунте».

## Последствия

- Подключить бота, прокси, ИИ или поменять расписание копий можно без доступа к серверу.
- Администратор, меняющий адреса внешних API, прокси и токены ботов, может направить через свой
  сервер то, что портал туда отправляет (сообщения ботов, запросы к ИИ). Это тот же уровень
  доверия, что и доступ к `.env` на сервере, который у помогающего с сервером обычно есть;
  каждое изменение видно в журнале аудита (`teacherbox.audit`) с именами переменных.
- Неверное значение, которое проверка пропустила (например, неподходящий токен), может помешать
  запуску. Тогда его исправляют или удаляют в `config/settings.properties` в папке данных —
  об этом говорит сообщение, если портал не вернулся за пять минут.
- Новая переменная окружения добавляется и в `.env.example`, и в `SettingsCatalog` — иначе
  тест каталога падает.
