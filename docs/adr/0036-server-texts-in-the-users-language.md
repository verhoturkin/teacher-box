# ADR-0036. Тексты сервера на языке пользователя

- Статус: принято
- Дата: 2026-10-12
- Дополняет: [ADR-0035](0035-interface-languages.md) (раздел «Последствия»)

## Контекст

С 0.11.0 интерфейс бывает русским и английским (ADR-0035), но выбор языка хранился только на устройстве, и
сервер о нём не знал. Тексты, которые пишет сервер, оставались русскими: уведомления во «Входящих» и в
мессенджерах, сообщения ботов, описания настроек администратора и проверки интеграций, названия занятий в
календарях (ICS-лента, Google Календарь).

Серверные тексты бывают двух видов:

- **ответ на запрос** — каталог настроек, проверки интеграций: читатель сейчас смотрит на страницу, её язык
  известен браузеру;
- **текст для кого-то потом** — уведомление ученику о переносе, ответ бота, календарь в чужом приложении:
  запроса от получателя нет, язык нужно знать заранее.

Варианты словарей на Java:

- `MessageSource` и `.properties` по модулям — стандартно для Spring, но ключи — строки (опечатка видна только
  в работе), а русские склонения в `ChoiceFormat` не выражаются.
- Свои словари — выбраны, по тем же причинам, что и словари TypeScript в ADR-0035.

## Решение

- **Языки** — `shared.i18n.Language` (`RU`, `EN`: код и локаль дат и чисел), те же, что в
  `core/i18n/language.ts`. Неизвестный или не заданный язык — русский.
- **Язык пользователя хранится в аккаунте** — `identity.users.language` (по умолчанию `ru`), задаётся
  `PUT /api/me/language`, отдаётся в `GET /api/me` и в пользователе сессии; другим модулям — через
  `UserDirectory.language(id)`. Браузер сохраняет в аккаунт язык, выбранный на устройстве, если он отличается
  (после входа и после перезагрузки страницы при смене языка). Устройство без своего выбора язык аккаунта не
  меняет: у пользователя с несколькими устройствами сервер пишет на языке последнего выбора.
- **Ответ на запрос** — на языке запроса: SPA ставит `Accept-Language` с языком страницы на каждый запрос к
  `/api` (иначе браузер прислал бы свои языки), сервер читает его через `Language.current()`
  (`spring.web.locale: ru` — без заголовка русский). Так работают каталог настроек и проверки интеграций:
  `platform` не знает модуль `identity` и не может спросить язык пользователя.
- **Текст для получателя** — на языке получателя на момент, когда текст написан: уведомление (во «Входящих» оно
  хранится готовым текстом, смена языка старые уведомления не переводит), сообщение бота (язык берётся из
  аккаунта, от имени которого действует чат), ICS-лента (язык владельца ленты), события Google Календаря (язык
  учителя). Чат, ещё не подключённый к аккаунту, получает ответы на языке учителя — это язык портала.
- **Словари** — рядом с кодом, в своём модуле: `enum` с константой на каждый язык и абстрактным методом на
  каждый текст (`RU { String cancelled() { return "Действие отменено."; } }`); тексты с числами и именами —
  методы с параметрами, склонения — правилами языка. Выбор словаря — `switch` по `Language` без `default`:
  новый язык — ошибка компиляции, пока его нет в каждом словаре; пропущенный текст — тоже ошибка компиляции.
  Тексты-данные (каталог настроек) — пары `ru`/`en` в одной записи.
- Бот понимает введённые слова обоих языков («да» / «yes», «сегодня» / «today»), какой бы язык ни был выбран.

## Последствия

- Новый язык на сервере: константа в `Language`, затем компилятор назовёт все словари, где её нет.
- Письма и уведомления, созданные до смены языка, остаются на прежнем языке.
- Тексты, которые вводят люди (сообщения учителя ученикам, названия групп, темы занятий), не переводятся.
- Подсказки ИИ (промпты) не зависят от языка интерфейса.
