# ADR-0063. Выпуск — это слияние в `main` новой версии; тег ставит CI

- Статус: принято
- Дата: 2026-11-12
- Уточняет: [ADR-0032](0032-ready-images-and-installer.md) и
  [ADR-0062](0062-native-runners-for-images.md) (что запускает публикацию образов)
- Действующие правила: `.github/workflows/ci.yml` (задания `version`, `image`, `publish`,
  `release`, `wiki`), `scripts/release-version.sh`, скилл `release`

## Контекст

Выпуск начинался с тега: агент или человек ставил тег `vX.Y.Z` на коммит выпуска и отправлял его
вместе с веткой, а CI на тег `v*` публиковал образы и вики. Это плохо работало:

- облачная сессия агента может отправлять коммиты только в свою ветку, отправка тега не проходит;
- тег ставился на коммит ветки до ревью и слияния; после слияния PR (squash, rebase или правка
  перед слиянием) тег указывал на коммит, которого нет в `main`, и его приходилось переносить;
- отправка тега — необратимый шаг (образы в GHCR, вики), который делала сессия, а не проверенный
  CI на `main`.

## Решение

- **Выпуск = слияние в `main` коммита с новой версией.** Коммит `chore(release): X.Y.Z` готовится в
  обычной ветке и PR, как раньше, но без тега. Версия — одна в `backend/pom.xml`,
  `frontend/package.json` и корне `frontend/package-lock.json`.
- **Задание `version`** (`scripts/release-version.sh`) идёт в каждом запуске CI: проверяет, что
  версия одна и это SemVer; версия новая, если тега `vX.Y.Z` на `origin` нет; у новой версии должен
  быть раздел `## [X.Y.Z]` в `CHANGELOG.md`. В PR это ловит ошибки выпуска до слияния; в `main`
  новая версия запускает выпуск.
- **Выпуск в том же запуске CI на `main`**, после всех проверок: `image` и `publish` (ADR-0062) с
  тегами образов `X.Y.Z`, `X.Y`, `latest` (у пре-релиза `X.Y.Z-…` — только `X.Y.Z`), затем
  `release` — тег `vX.Y.Z` на проверенный коммит `main` и GitHub Release с текстом раздела
  CHANGELOG, затем `wiki`.
- **Тег — последним.** Пока тега нет, выпуск не состоялся: неудачный выпуск повторяет «Re-run failed
  jobs» или следующий push в `main` (он выпускает ту же версию со своего коммита). Шаги `release`
  повторяемы: тег на том же коммите и существующий релиз не трогаются, тег на другом коммите —
  ошибка.
- **Тег ставит `GITHUB_TOKEN`**, поэтому он не запускает другие workflow; триггер `tags: ['v*']`
  убран, всё делается в одном запуске. Ручной запуск CI (`workflow_dispatch`) оставлен.
- **Запуски `main` не отменяются** (`cancel-in-progress` только для PR): новый push не обрывает
  идущий выпуск, а заменяет только ожидающий запуск.

## Последствия

- Агенту не нужен пуш тегов: выпуск — это PR, который сливает человек.
- Тег всегда указывает на коммит `main`, прошедший все проверки, и появляется вместе с GitHub
  Release.
- Поднять версию без выпуска в `main` нельзя: слияние новой версии и есть выпуск. Слить её без
  раздела CHANGELOG не даст красная проверка PR.
- Защита тегов `v*` (ruleset: создавать может только GitHub Actions) и неизменяемые релизы
  включаются в настройках репозитория вручную.
- Образы выпуска по-прежнему собираются для выпуска заново (в них зашита `VERSION`), а не
  перемечаются из образов проверок `main`.
