# ADR-0008. Расписание занятий и календари

- Статус: принято
- Дата: 2026-09-26

## Контекст

Учитель ведёт занятия по расписанию: разовые и регулярные (например, по вторникам и четвергам
в 18:00). Ученики должны знать о занятиях, получать напоминания и иметь возможность попросить
перенос или отмену. Проведённое или пропущенное занятие начисляется в оплатах (`billing`), но
модуль оплат не должен знать о расписании больше, чем нужно для начисления.

## Решение

- Новый модуль `schedule` (зависит от `shared`, `identity::api`), своя схема: `series`,
  `lessons`, `change_requests`, `reminders_sent`, `feeds`.
- **Время.** Занятие хранит начало как `Instant` (UTC). Серия хранит дни недели, местное время и
  даты в часовом поясе инстанса (`TEACHERBOX_TIMEZONE`): переход на летнее время не сдвигает
  уроки. Интерфейс получает часовой пояс из `GET /api/me/schedule/settings`.
- **Серии.** Занятия серии создаются заранее на горизонт (`TEACHERBOX_SCHEDULE_HORIZON`,
  по умолчанию 84 дня) и продлеваются ночью. Серия не меняется «на месте»: изменение с даты
  завершает старую серию накануне и создаёт новую; будущие занятия старой серии удаляются, кроме
  перенесённых по отдельности (это отдельные договорённости). Уникальность `(series_id,
  series_date)` защищает от дублей.
- **Пересечения.** Учитель один, поэтому любое пересечение занятий — конфликт (`409
  schedule.overlap`); интерфейс переспрашивает и повторяет запрос с `allowOverlap`.
- **Перенос и отмена.** Учитель меняет расписание сам. Ученик только отправляет запрос
  (перенос с предложенным временем или отмена); учитель согласует или отклоняет. Отмена позже
  `TEACHERBOX_SCHEDULE_LATE_CANCELLATION` (по умолчанию 24 ч) помечается как поздняя —
  учитель решает, засчитать ли её как пропуск. Если учитель сам меняет занятие с открытым
  запросом, запрос становится неактуальным (`OUTDATED`).
- **Итог и оплата.** После начала учитель отмечает «Проведено» или «Пропуск»; событие
  `LessonCompleted` несёт `completionId`. `billing` слушает его (зависимость `schedule::api`,
  только события) и начисляет занятие по тарифу ученика, запоминая `completionId` —
  повторная доставка события не создаёт второго начисления. Исправление итога публикует
  `LessonCompletionRevoked`, и `billing` отменяет начисление (запись остаётся в истории).
- **Напоминания.** Планировщик раз в 5 минут публикует `LessonStartingSoon` за интервалы
  `TEACHERBOX_SCHEDULE_REMINDERS` (по умолчанию `24h,1h`), по одному на интервал; если
  подошли сразу несколько (занятие назначено за полчаса), отправляется только ближайшее.
  Перенос сбрасывает отправленные напоминания. Ученик получает все напоминания, учитель —
  только последнее.
- **Календари.** Лента iCalendar (RFC 5545) по секретной ссылке
  `/api/public/schedule/<token>.ics`: у учителя — все занятия с именами учеников, у ученика —
  только свои. Токен — 256 случайных бит, хранится хеш, ссылка показывается один раз и
  перевыпускается. Префикс `/api/public/**` открыт без входа. Двусторонняя интеграция с Google
  Календарём учителя — отдельный этап (OAuth).
- Уведомления о расписании формирует `notifications` по событиям; изменения по запросу
  ученика объявляются один раз — ответом на запрос.

### Google Календарь учителя (этап 15)

- Подключение — **OAuth 2.0 для веб-серверных приложений** с OAuth-клиентом из Google Cloud
  проекта учителя (client id/secret в настройках или в переменных окружения, переменные важнее).
  Минимальный scope `calendar.app.created`: портал создаёт свой календарь «Teacher Box» и
  работает только с ним; по желанию — `calendar.freebusy` для занятости основного календаря.
- `redirect_uri` = адрес, по которому учитель открыл портал, + `/api/public/schedule/google/callback`
  (подключение через `http://localhost` по SSH-туннелю работает без публичного адреса). Браузер
  приходит туда без токена портала, поэтому запрос авторизует одноразовый `state` (256 бит,
  хранится хеш, 10 минут). `prompt=consent` + `access_type=offline` гарантируют refresh token.
- Синхронизация односторонняя, каждую минуту: занятия окна «неделя назад — горизонт» с версией,
  отличной от отправленной, записываются в календарь (`PUT` события, при 404 — создание с
  собственным id = id занятия без дефисов), отменённые и удалённые (изменённые серии) —
  удаляются. Сетевые вызовы вне транзакций. `invalid_grant`/401 → статус «нужно подключить
  заново» и уведомление учителю (`GoogleCalendarDisconnected`).
- Секреты (client secret, refresh token) хранятся в БД и не отдаются в браузер; при отключении
  токен отзывается, календарь «Teacher Box» остаётся у учителя.

## Последствия

- (+) Оплаты не знают о расписании, кроме события с итогом; расписание не знает о ценах.
- (+) Календари работают в Google, Apple и Яндекс без настроек интеграций; Google обновляет
  подписанные ленты с задержкой — мгновенную синхронизацию даст этап с Google API.
- (−) Групповых занятий нет: одно занятие — один ученик.
