# ADR-0030. Встроенные видеозвонки на LiveKit

- Статус: принято
- Дата: 2026-10-06
- Заменяет: [ADR-0012](0012-meetings-and-boards.md) в части «Телемост» (API Телемоста, подключение Яндекса)
- Действующие правила: [docs/modules/meetings.md](../modules/meetings.md)

## Контекст

С 1.3 уроки идут во внешней видеосвязи: учитель вставляет ссылку или создаёт встречу Телемоста через API
(подключение Яндекс ID, OAuth). Это работает не у всех (API принимает не всякий аккаунт), уводит ученика из
портала и не даёт учителю видеть, кто уже ждёт. Нужны звонки внутри портала — один на один и группой, — у
каждого ученика и группы своя постоянная комната, а окно звонка можно свернуть и продолжать работать в
портале (доски, задания).

## Решение

### Медиасервер — LiveKit, свой

- **LiveKit server** (Apache-2.0, образ `livekit/livekit-server`, закреплённая версия) — отдельный контейнер
  рядом с порталом, профиль Compose `calls`; без профиля портал работает как раньше, только с внешними
  ссылками. Портал по-прежнему один на учителя — один экземпляр LiveKit без Redis.
- **Медиа** идёт напрямую браузер ↔ LiveKit: UDP 7882 (один порт, мультиплексирование), запасной TCP 7881,
  встроенный TURN по UDP 3478 для сетей за NAT. Эти порты открываются на сервере; публичный адрес LiveKit
  определяет сам (`use_external_ip`) или берёт из `TEACHERBOX_LIVEKIT_NODE_IP`.
- **Сигнализация** (WebSocket) идёт через адрес портала: `wss://<портал>/livekit` → `livekit:7880`. Клиент
  сохраняет подпуть (`/livekit/rtc/v1`, проверено по исходникам `livekit-client` 2.22), поэтому TLS и
  сертификат — те же, что у портала, а CSP `connect-src 'self'` не меняется. В варианте split прокси —
  nginx фронтенда; в варианте single (без nginx) правило `/livekit/` добавляют в свой обратный прокси
  (`docs/operations.md`). Браузер всегда идёт на `<свой адрес>/livekit`; LiveKit на другом сервере
  подключается тем же прокси (`LIVEKIT_URL` nginx варианта split или свой прокси) и
  `TEACHERBOX_MEETINGS_LIVEKIT_API_URL` — отдельного адреса для браузера и правки CSP нет.

### Комнаты и доступ

- Комната ученика или группы — `tb-<ownerId>`. Комнаты **нигде не хранятся**: LiveKit создаёт комнату при
  первом входе и закрывает пустую по таймауту. Таблица `rooms` модуля хранит только внешние ссылки.
- Войти можно только с **токеном**, который выдаёт бэкенд (`POST /api/meetings/calls/{ownerId}/token`):
  учитель — в любую комнату текущего ученика или активной группы, ученик — в свою и в комнаты своих групп
  (иначе 404), администратор — никуда. Токен подписан ключом API (HS256), живёт недолго (нужен только для
  подключения, дальше LiveKit продлевает его сам); identity — id пользователя, имя — отображаемое имя;
  учитель — `roomAdmin`.
- Ученик может войти в комнату в любое время; учитель видит в разделе «Звонки», кто уже в комнате.
- Отчисленного ученика и исключённого из группы участника бэкенд удаляет из комнаты
  (`RoomService.RemoveParticipant`).
- Звонки включены, когда заданы ключ и секрет API (`TEACHERBOX_MEETINGS_LIVEKIT_API_KEY/SECRET`); их же
  получает контейнер LiveKit (`LIVEKIT_KEYS`).

### Ссылки

- Порядок: ссылка занятия → внешняя ссылка ученика или группы → встроенная комната. Ссылка встроенной
  комнаты — обычная ссылка портала `Portal.link("/call/<ownerId>")`, поэтому напоминания, календари (ICS),
  бот и «Отправить ученику» работают без изменений; портал узнаёт такую ссылку и открывает звонок у себя.
- Ссылки, созданные раньше через API Телемоста, остаются внешними ссылками; чтобы перейти на встроенную
  комнату, учитель удаляет ссылку.
- Открытие ссылок Телемоста в приложении на компьютере (настройка устройства) остаётся — это не API.

### Библиотеки

- Бэкенд — официальный **`io.livekit:livekit-server`** (Apache-2.0): `AccessToken`, `RoomServiceClient`.
  Он тянет Kotlin stdlib, Retrofit, protobuf и OkHttp 5; OkHttp выровнен BOM на 5.x для всех (клиент
  Anthropic с ним работает — его тесты зелёные). Вызовы LiveKit — вне транзакций, с таймаутами.
- Фронтенд — **`livekit-client`** (Apache-2.0, ADR-0007), загружается отдельным чанком (≈ 580 КБ, 126 КБ
  сжатым) только при входе в звонок; окно звонка — блок `@defer (on idle)` в корне, маршрут `/call/…` —
  `loadChildren`, поэтому стартовый бандл вырос лишь на ≈ 15 КБ.

### Интерфейс

- Окно звонка живёт в корне приложения (над макетами), поэтому звонок не прерывается при переходах, в том
  числе на полноэкранную доску. Два вида: развёрнутый (сцена, плитки, плавающая панель M3 Expressive) и
  свёрнутый (мини-окно на компьютере, полоса над нижней навигацией на телефоне). Цвета — токены темы
  портала (светлая/тёмная по системе).
- `Permissions-Policy` разрешает своему адресу камеру, микрофон и показ экрана
  (`camera=(self), microphone=(self), display-capture=(self)`).

Отвергнутые варианты:

- **Оставить API Телемоста.** Не у всех аккаунтов работает, ученик уходит из портала, статуса комнаты нет.
- **Jitsi Meet.** Несколько контейнеров (web, prosody, jicofo, jvb), встраивание — iframe со своим
  интерфейсом, не по дизайн-системе портала.
- **mediasoup / свой SFU.** Свой сервер сигнализации и много низкоуровневого кода.
- **LiveKit Cloud.** Данные уроков у стороннего сервиса, а браузеру понадобился бы другой адрес и своя CSP
  (в варианте split она задана в nginx статически).
- **Свой клиент Twirp вместо SDK.** Меньше зависимостей, но SDK официальный и покрывает токены и вебхуки;
  конфликт OkHttp решён выравниванием версии.

## Последствия

- Для звонков нужен ещё один контейнер и открытые порты 7881/tcp, 7882/udp, 3478/udp; без них портал
  работает с внешними ссылками.
- Свой обратный прокси перед порталом должен пропускать WebSocket на `/livekit/`.
- Таблицы подключения Яндекса удалены (миграция `meetings` V2); переменные `TEACHERBOX_MEETINGS_YANDEX_*` и
  `TEACHERBOX_MEETINGS_TELEMOST_*` больше не читаются.
- Истории звонков нет; вебхуки LiveKit не используются (статус комнат — запросом `ListRooms`).
