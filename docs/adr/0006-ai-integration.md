# ADR-0006. Интеграция с ИИ: независимый модуль с провайдер-агностичным SPI

- Статус: принято
- Дата: 2026-09-25

## Контекст

Учителю полезны: генерация черновиков ДЗ и черновик проверки ответа ученика. Self-hosted
пользователи используют разных провайдеров (Anthropic, OpenAI, OpenRouter, локальные модели
через Ollama/LM Studio). Расходы на ИИ должны быть под контролем.

## Решение

- Модуль `ai` зависит **только** от `shared`. Он не читает данные ДЗ: фронтенд передаёт тексты
  в запросе. Так `homework` и `ai` остаются полностью независимыми.
- SPI `LlmClient` с двумя адаптерами:
  - `anthropic` — Messages API через **официальный Java SDK** (`com.anthropic:anthropic-java`):
    типизированные запросы и ошибки, актуальные параметры моделей без ручного JSON;
  - `openai-compatible` — `/chat/completions` на `RestClient` (OpenAI, OpenRouter, Ollama,
    LM Studio, vLLM и т.п.).
- Провайдер, модель, ключ, базовый URL — переменные окружения (`TEACHERBOX_AI_*`).
  Без настройки модуль выключен, UI скрывает ИИ-функции.
- Доступ к ИИ — только у учителя (на v1). Учёт токенов в схеме `ai`, месячный лимит.
- Промпты — ресурсы модуля с версионированием; ответы ИИ — всегда черновик, который
  учитель редактирует и подтверждает сам.

### Уточнения реализации (этап 8)

- Модель Anthropic по умолчанию — `claude-opus-5`; параметр `thinking` не передаётся (у модели по
  умолчанию адаптивное мышление, а другие модели из настройки продолжают работать), `effort`
  настраивается (`TEACHERBOX_AI_EFFORT`, по умолчанию — значение модели).
- Формат ответа задаётся JSON Schema: у Anthropic — structured outputs (`output_config.format`),
  у OpenAI-совместимых — `response_format: json_schema`; ответ дополнительно разбирается
  «терпимо» (Markdown-обёртки) и валидируется.
- Отказы модели (`stop_reason: refusal`) обрабатываются до чтения ответа. Включены серверные
  fallbacks Anthropic (`fallbacks: "default"`, beta `server-side-fallback-2026-07-01`):
  отклонённый запрос повторяется на рекомендованной модели; отключается
  `TEACHERBOX_AI_FALLBACKS=false` (например, для прокси, не знающих параметр).
- В журнале `ai.requests` — только метаданные (фича, модель, статус, токены, длительность,
  ошибка); тексты заданий и ответов учеников не сохраняются.
- Лимит — сумма входных и выходных токенов за календарный месяц в часовом поясе инстанса;
  при исчерпании запросы отклоняются до вызова провайдера.
- Тесты адаптера Anthropic идут против локального HTTP-сервера (SDK работает на OkHttp, поэтому
  `MockRestServiceServer` не подходит); OpenAI-совместимого — через `MockRestServiceServer`.

### Gemini (версия 1.1)

- Подписку Google AI Pro/Ultra использовать нельзя: её преимущества действуют только в
  веб-интерфейсе Google AI Studio, вызовы Gemini API оплачиваются отдельно, а использование
  OAuth-токенов Gemini CLI сторонними программами нарушает условия Google (блокировки
  аккаунтов с февраля 2026). Официальной программы для сторонних приложений нет.
- Поэтому Gemini подключается **по ключу Gemini API** (Google AI Studio): провайдер `gemini`
  использует OpenAI-совместимый endpoint `https://generativelanguage.googleapis.com/v1beta/openai`
  и тот же адаптер, что `openai-compatible` (JSON Schema в `response_format`). Модель по
  умолчанию — `gemini-3.8-flash`. Если совместимый endpoint перестанет справляться со схемами
  ответов, заменить адаптер на официальный Java SDK `google-genai`.
- Gemini API недоступен из России — нужен `TEACHERBOX_AI_PROXY` (ADR-0009). На бесплатном
  уровне Google может использовать тексты запросов для улучшения своих продуктов — README
  предупреждает об этом, ведь в запросах бывают ответы учеников.
- Неизвестное значение `TEACHERBOX_AI_PROVIDER` останавливает запуск (раньше опечатка молча
  выключала ИИ).

## Последствия

- (+) Смена провайдера — только конфигурация.
- (+) Данные учеников уходят во внешний сервис лишь по явному действию учителя.
- (−) Возможности, специфичные для провайдера (tool use и т.п.), не используются на v1.
