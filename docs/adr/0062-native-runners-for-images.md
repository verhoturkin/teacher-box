# ADR-0062. Образы каждой платформы собираются на раннере своей архитектуры

- Статус: принято
- Дата: 2026-11-12
- Дополняет: [ADR-0032](0032-ready-images-and-installer.md) (как CI собирает образы `amd64` и
  `arm64`)
- Действующие правила: `.github/workflows/ci.yml` (задания `image` и `publish`), `docker/Dockerfile`

## Контекст

Задание `publish` собирало оба образа одной командой `platforms: linux/amd64,linux/arm64` на
`ubuntu-latest`. Стадии Maven и npm уже шли на платформе сборщика (`$BUILDPLATFORM`, ADR-0032), но
стадия `backend-aot` — пробный запуск JVM для кеша AOT — по своей сути принадлежит платформе образа:
кеш действителен только для той JVM, которая его записала. Для `arm64` этот запуск (Spring
поднимает все бины и прогоняет миграции пустой базы) шёл под эмуляцией QEMU и занимал большую часть
времени выпуска. Перенести его на `$BUILDPLATFORM` нельзя: кеш `amd64` не годится для JVM `arm64`.

## Решение

- **Нативные раннеры.** Задание `image` — матрица «образ × архитектура»: `amd64` на
  `ubuntu-latest`, `arm64` на `ubuntu-24.04-arm`. QEMU не ставится; каждая сборка однородна
  (`platforms: linux/<arch>`), пробный запуск AOT идёт на настоящем процессоре своей архитектуры.
- **Публикация по digest.** Каждая сборка отправляет образ в GHCR без тега
  (`push-by-digest=true`) и сохраняет digest как артефакт. Задание `publish` для каждого образа
  собирает индекс из двух digest командой `docker buildx imagetools create` с прежними тегами
  `X.Y.Z`, `X.Y` и `latest` и проверяет, что в индексе обе архитектуры.
- **Кеш слоёв** `type=gha` — отдельный scope на образ и архитектуру (`backend-amd64`,
  `backend-arm64`, …): сборки разных платформ не вытесняют кеш друг друга.
- `docker/Dockerfile` не меняется по сути: кросс-сборка стадий Maven/npm остаётся для локальной
  сборки под другую платформу (там `backend-aot` по-прежнему эмулируется).

## Последствия

- Выпуск быстрее: самая долгая стадия `arm64` больше не эмулируется; четыре сборки идут
  параллельно.
- Jar и SPA собираются на каждом раннере заново (в `amd64` и `arm64` — свои копии); каждый образ
  целен сам по себе, побайтовое совпадение jar между платформами не требуется.
- Раннеры `ubuntu-24.04-arm` бесплатны для публичных репозиториев; для закрытого нужен платный
  план или свой раннер.
- Проверки pull request (задание `images`, сборка `amd64` и проверка кеша AOT) не меняются.
- Пакет в GHCR получает до тегирования безымянные версии (по одной на платформу); теги ставит
  только индекс.
