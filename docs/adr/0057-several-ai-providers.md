# ADR-0057: Несколько ИИ-провайдеров

Дата: 2026-11-10. Статус: принято. Дополняет ADR-0006 и ADR-0056.

## Контекст

ИИ-помощник настраивается переменными `TEACHERBOX_AI_*`: один сервис, одна модель. Учитель хочет
держать несколько подключений (например, Claude для проверок и дешёвую модель для черновиков) и
переключаться между ними без администратора и перезапуска. По ADR-0056 такие настройки учителя
живут в схеме модуля, а `.env` читается для них один раз.

## Решение

- В схеме `ai` три таблицы (миграция `V4__providers.sql`):
  - `providers` — подключение: вид (`anthropic`, `gemini`, `openrouter`, `deepseek`,
    `openai-compatible`), имя 1–60, ключ API, адрес API, прокси, порядок, версия;
  - `models` — модели подключения: идентификатор модели 1–120 (уникален в подключении), подпись
    1–60, усилие, запасная модель, предел токенов ответа, время ожидания, порядок, версия;
    удаляются вместе с подключением;
  - `settings` — одна строка: модель по умолчанию и месячный лимит токенов (один на все модели);
    удалённая модель по умолчанию сбрасывается в `null` — ИИ выключен, пока учитель не выберет
    другую.
  В `ai.requests` добавлен `model_id` — какая из настроенных моделей отвечала (`null` у старых
  записей); имена провайдера и модели в записи остаются.
- Ключ хранится как токены мессенджеров: открыто в схеме модуля и в резервных копиях; полный сброс
  удаляет подключения, модели и настройки (ADR-0014). Резервная копия — снимок всей базы, новые
  таблицы попадают в неё без отдельной настройки.
- Клиенты строит `LlmClients`: `forModel(modelId)` и `forDefault()`. Каждый вид подключения —
  адаптер (SPI `LlmAdapter` в пакетах `anthropic/`, `openai/`, `gemini/`, `openrouter/`,
  `deepseek/`) вместо условных бинов по `TEACHERBOX_AI_PROVIDER`. Клиенты хранятся по подключению
  и создаются при первом запросе; изменение подключения или модели (их версия) и смена
  действующего прокси сбрасывают клиенты подключения, следующий запрос строит их заново. Запрос,
  уже идущий через сброшенный клиент, завершается; при остановке портала закрываются оставшиеся
  клиенты. Подключение, которое нельзя вызвать (нет ключа, адреса, неверный прокси), не ломает
  запуск: его запросы и проверка отвечают ошибкой с причиной.
- Прокси: у подключения свой прокси, без него — `TEACHERBOX_AI_PROXY`. Это настройка
  администратора с пометкой `live` (ADR-0056): `.env` > интерфейс > умолчание, применяется сразу.
- Запросы черновиков принимают необязательный `modelId`; без него работает модель по умолчанию,
  неизвестная или удалённая модель — 409 `ai.model.unknown` с названием модели по умолчанию.
  Выбор модели хранится на устройстве (`localStorage`), не на сервере.

## Перенос

- Переменные `TEACHERBOX_AI_*`, кроме прокси, — настройки учителя. `ai.AiSettingsImport`
  (SPI `shared.settings.TeacherSettingsImport`) при первом запуске новой версии создаёт из них
  подключение (имя — название сервиса) и одну модель (модель из `TEACHERBOX_AI_MODEL` или модель
  сервиса по умолчанию, подпись — её идентификатор), делает её моделью по умолчанию и переносит
  месячный лимит. Если подключения уже есть, ничего не переносится. Неполная настройка (неизвестный
  сервис, нет ключа, модели или адреса) не переносится, лимит — переносится.
- Переменные ИИ ушли из `.env.example`; в каталоге настроек они остаются только для переноса и
  списка «Перенесено в настройки учителя».

## Последствия

- Учитель держит несколько подключений и моделей и меняет их без перезапуска.
- Неверный прокси ИИ больше не останавливает запуск — ошибка видна в запросе и в проверке
  интеграций.
- Лимит по моделям не делится (вне рамок): расход по моделям показывается отдельно.
- Регрессии проверяет E2E `e2e/tests/ai/providers.spec.ts` на имитации провайдера
  (`e2e/ai-mock`, OpenAI-совместимый API).
