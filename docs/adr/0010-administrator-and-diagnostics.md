# ADR-0010. Администратор и диагностика

- Статус: принято
- Дата: 2026-09-26

## Контекст

Портал ставят на свой сервер или NAS. Когда что-то ломается (не приходят сообщения в Telegram,
ИИ отвечает ошибкой, «Произошла ошибка» у ученика), учителю нечего показать тому, кто помогает
с сервером: журнал лежит в выводе контейнера, уровень логирования меняется только перезапуском,
а зайти в кабинет учителя помощнику нельзя — там данные учеников.

## Решение

### Роль `ADMIN`

- Одна учётная запись администратора из `TEACHERBOX_IDENTITY_ADMIN_LOGIN` (по умолчанию
  `admin`) и `TEACHERBOX_IDENTITY_ADMIN_PASSWORD`. **Пароль не задан — администратора нет:**
  существующая учётная запись отключается при запуске. Пароль из переменной применяется при
  создании и при повторном включении; дальше администратор меняет его сам.
- Если логин занят учеником, администратор не создаётся, в журнале — ошибка с объяснением.
- Администратору доступны только `/api/admin/**`, `/api/me` и смена своего пароля. Остальной
  `/api/**` требует роли `TEACHER` или `STUDENT`, поэтому кабинет ученика и данные учителя ему
  закрыты на уровне Spring Security, а не проверками в контроллерах.
- Администратор **не видит данные учеников**: имён, оплат, работ, текстов уведомлений. В его
  разделах — технические данные и идентификаторы. Журнал не должен содержать персональных
  данных: в сообщениях журнала пишутся идентификаторы, а не имена и тексты.
- Действия администратора (смена уровня логирования, повтор событий и доставок, выгрузка
  диагностики) пишутся в журнал с логгером `teacherbox.audit` (там же, где входы в систему) — их видно в
  поиске по журналу.

### Журнал и код ошибки

- Журнал пишется в `/data/logs/teacher-box.log` в формате JSON (ECS, структурированное
  логирование Spring Boot) с ротацией по размеру; вывод в консоль остаётся текстовым.
- У каждого запроса есть код (`X-Request-Id`: принимается от прокси или создаётся), он попадает
  в MDC, в заголовок ответа и в поле `requestId` каждого ProblemDetail. Интерфейс показывает его
  в сообщении об ошибке сервера — учитель называет код администратору, тот находит запрос в
  журнале.
- Ошибки браузера отправляются на `/api/client-errors` (без входа, с ограничением частоты) и
  попадают в тот же журнал.

### Разделы администратора

- `platform` (знает только `shared`): поиск по журналу, уровни логирования на время с
  автоматическим возвратом, состояние (версия, время работы, память, диск, размер БД, health),
  незавершённые события Modulith с повторной отправкой, проверка интеграций, диагностический
  архив (журнал, настройки `teacherbox.*` со скрытыми секретами, версии).
- Проверки интеграций — SPI `shared.diagnostics.IntegrationCheck`: каждый модуль сам проверяет
  своё (бот мессенджера через его прокси, провайдер ИИ без расхода токенов, Google Календарь),
  `platform` только собирает результаты. Так `platform` по-прежнему не знает о бизнес-модулях.
- Данные модулей для администратора — эндпоинты `/api/admin/<module>/**` в самих модулях:
  неудачные доставки с повтором (`notifications`, без текстов и имён), журнал запросов к ИИ
  (`ai`, только метаданные).

## Последствия

- Администратор — техническая роль без доступа к данным учеников; помощь с сервером не требует
  входить под учителем.
- Журнал на диске занимает место: ротация ограничивает его (по умолчанию 10 файлов по 10 МБ),
  настраивается переменными `LOGGING_LOGBACK_ROLLINGPOLICY_*`.
- Поиск читает файлы журнала построчно; для журнала в десятки мегабайт этого достаточно.
