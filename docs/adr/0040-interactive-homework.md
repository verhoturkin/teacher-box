# ADR-0040. Интерактивное домашнее задание: HTML в песочнице

- Статус: принято
- Дата: 2026-10-12

## Контекст

В 0.14.0 у домашнего задания появляется тип «Интерактивное»: учитель (или ИИ) пишет HTML-страницу с
вопросами и проверкой, ученик решает прямо на ней и нажимает «Готово». Страница — чужой код со скриптами:
его пишет учитель, копирует из интернета или генерирует ИИ.

Ограничения:

- **CSP портала** — `script-src 'self'`; `srcdoc`- и `blob:`-фреймы наследуют политику документа, который их
  создал, поэтому встроенные скрипты страницы в них не запустятся. Ослаблять политику всего портала ради
  одного типа заданий нельзя.
- **Безопасность.** Скрипт страницы не должен видеть токен входа (он в памяти и `localStorage` портала),
  вызывать API от имени ученика или учителя, уводить на другой сайт или подгружать что-то извне.
- **Ответ** ученика нужен учителю: баллы и ответы, которые посчитала страница.
- nginx добавляет заголовки безопасности сам на уровне сервера и скрывает заголовки бэкенда (ADR-0031).

## Решение

1. **Хранение.** HTML лежит в задании как есть (`homework.assignments.interactive_html`, до 200 000
   символов) и никогда не вставляется в документ портала.
2. **Отдельный адрес.** `GET /api/public/homework/interactive/{token}` отдаёт страницу со своей политикой:
   `sandbox allow-scripts; default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline';
   img-src data:; font-src data:; media-src data:; base-uri 'none'; form-action 'none'; frame-ancestors 'self'`,
   `X-Frame-Options: SAMEORIGIN`, `Cache-Control: no-store`, `Referrer-Policy: no-referrer`. `sandbox` без
   `allow-same-origin` даёт странице непрозрачный источник — даже открытая напрямую, она не видит ни cookie,
   ни хранилища, ни API портала. nginx для этого пути ставит те же заголовки, а платформа выставляет
   `X-Frame-Options: DENY` только тем ответам, которые не задали его сами.
3. **Ссылка** — подписанная HMAC-SHA256 (задание + срок, 5 минут) и выдаётся только тем, кому задание видно:
   учителю (`/api/teacher/homework/assignments/{id}/interactive-link`) и ученику задачи
   (`/api/me/homework/tasks/{id}/interactive-link`). Ключ создаётся в памяти при старте: перезапуск лишь
   закрывает открытые ссылки, хранить нечего. Испорченная или просроченная ссылка — 404.
4. **Показ.** Портал показывает страницу в `<iframe sandbox="allow-scripts">`. В начало страницы (после
   `<!doctype>`, до её собственных скриптов) вставляется скрипт-мост: он сообщает высоту (`teacherbox:height`) и даёт странице `teacherbox.result({score, maxScore,
   answers})` (`teacherbox:result`). Портал принимает сообщения только от своего фрейма (`event.source`) и
   проверяет их форму.
5. **Ответ.** «Готово» (`POST /api/me/homework/tasks/{id}/done`) отправляет последний результат страницы;
   он хранится в ответе (`submissions.result`, JSON) и показывается учителю как подсказка, не как оценка —
   страница работает в браузере ученика, её результат можно подделать.

## Последствия

- Скрипты страницы работают, но ничего не могут сделать за её пределами: ни запросов к API, ни внешних
  ресурсов, ни переходов, ни отправки форм. Картинки и шрифты — только `data:`.
- Страница не видит стилей портала: оформление «под приложение» задаётся в самой странице (ИИ получает
  цвета и шрифты портала в запросе, этап 167).
- Новый тип ответа «Готово» без текста и файлов используется и для заданий «На доске».
- Заголовки страницы заданы в двух местах — `InteractivePageController` и nginx — и должны совпадать.
