# ADR-0003. Аутентификация: приглашения, JWT и ротация refresh-токенов

- Статус: принято
- Дата: 2026-09-25

## Контекст

Один учитель, много учеников. Открытой регистрации нет. SPA на Angular, в варианте split —
за nginx на том же origin. Система self-hosted, часто за NAT, без внешнего IdP.

## Решение

- **Учитель** создаётся при первом старте из `TEACHERBOX_TEACHER_LOGIN` /
  `TEACHERBOX_TEACHER_PASSWORD`. Если пароль не задан — генерируется и один раз выводится в лог.
  Инвариант «ровно один учитель» обеспечивается в домене и уникальным ограничением в БД.
- **Ученик** создаётся учителем; система выдаёт одноразовую ссылку-приглашение
  (случайный токен 256 бит, хранится SHA-256, срок жизни 7 дней). По ссылке ученик задаёт логин
  и пароль. Перевыпуск приглашения аннулирует предыдущее.
- **Пароли** — `DelegatingPasswordEncoder` (bcrypt по умолчанию), минимальная длина 8.
- **Access-токен** — JWT HS256 (Spring Security OAuth2 Resource Server + Nimbus), 15 минут,
  claims: `sub` (userId), `role`, `name`. Хранится только в памяти SPA.
  Ключ — `TEACHERBOX_JWT_SECRET` или сгенерированный при первом старте и сохранённый в `/data/keys`.
- **Refresh-токен** — случайный, в БД хранится хеш; cookie `HttpOnly; Secure (в prod);
  SameSite=Strict; Path=/api/auth`. Каждое обновление ротирует токен; повторное использование
  старого токена отзывает всё «семейство» (признак кражи).
- **Защита от перебора** — счётчик неудачных попыток на учётную запись, временная блокировка.
- **Деактивация ученика** — отзыв всех refresh-токенов; access-токен истекает сам (≤ 15 мин).

## Последствия

- (+) Нет серверных сессий — перезапуск не разлогинивает (refresh в БД).
- (+) XSS не может украсть refresh-токен (HttpOnly), CSRF невозможен из-за SameSite=Strict
  и того, что остальные API требуют заголовок `Authorization`.
- (−) Отзыв access-токена не мгновенный (до 15 минут) — приемлемо для домена.
