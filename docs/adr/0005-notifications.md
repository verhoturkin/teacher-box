# ADR-0005. Уведомления: inbox + outbox + адаптеры каналов

- Статус: принято
- Дата: 2026-09-25

## Контекст

Ученики (и учитель) должны получать уведомления в ЛК, в Telegram-боте и в личные сообщения
мессенджеров. Внешние API ненадёжны; инстанс часто работает без публичного URL (за NAT).
Модули-источники событий не должны знать о способах доставки.

## Решение

- `notifications` подписывается на доменные события других модулей (`HomeworkAssigned`,
  `PaymentRecorded`, ...) через `@ApplicationModuleListener`. Источники о нём не знают.
- Каждое уведомление: запись в **inbox** (ЛК) + по записи в **outbox** (`deliveries`) на каждый
  подключённый и включённый внешний канал получателя.
- `DeliveryDispatcher` (планировщик) отправляет outbox-записи, ретраи с экспоненциальной
  задержкой, после N попыток — `FAILED` с текстом ошибки (виден учителю).
- SPI `MessengerChannel` (`channel()`, `send(externalId, message)`); реализации:
  - **Telegram** — Bot API через `RestClient`, получение апдейтов **long polling**
    (`getUpdates`) — работает без публичного адреса. Привязка — deep-link
    `https://t.me/<bot>?start=<одноразовый токен>`.
  - **VK** — сообщения сообщества (`messages.send`), **MAX** — Bot API. Привязка — одноразовый
    код, который пользователь отправляет боту/сообществу.
- Каналы включаются переменными окружения; без токена канал просто недоступен в UI.
- Тексты уведомлений — шаблоны внутри модуля (русский язык).

## Последствия

- (+) Отказ внешнего API не влияет на бизнес-операции; доставка гарантирована ретраями.
- (+) Новый мессенджер = новая реализация `MessengerChannel` без изменений в других модулях.
- (−) Доставка во внешние каналы асинхронна (задержка — до интервала диспетчера, по умолчанию 5 с).
