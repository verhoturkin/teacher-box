# Версия 0.2 — архив плана (этапы 20–28)

Цели: групповые занятия, видеовстречи в Яндекс Телемосте, доски Холста у учеников и групп,
работа через ботов для учеников и учителя, справка по приложению. Этапы идут в порядке
зависимостей: группы нужны расписанию, встречам и доскам; основа диалогов в ботах — до
действий модулей; справка пишется последней, когда интерфейс устоялся.

Итоги исследования:

- **Яндекс Телемост.** API (`https://cloud-api.yandex.net/v1/telemost-api`, OAuth-токен
  Яндекс ID со scope `telemost-api:conferences.*`) доступен только пользователям Яндекс 360
  для бизнеса с аккаунтом на домене организации. С личным аккаунтом ссылка встречи создаётся в
  Телемосте вручную. Приложение для ПК открывается ссылкой
  `telemost://https://telemost.yandex.ru/j/<номер>` — так его открывает сам веб-клиент
  Телемоста. Схема не документирована, поэтому рядом всегда есть обычная ссылка (её страница
  тоже предлагает открыть приложение).
- **Холст.** Публичный API (персональные токены) даёт только чтение журнала аудита
  организаций, API для досок нет. Доски умеет менять только локальный MCP-сервер (бета)
  приложения Холст для ПК (`127.0.0.1:47641`), с сервера портала он недоступен. Поэтому в 0.2 —
  доски по ссылкам и перенос материалов через буфер обмена; автоматизация — когда у Холста
  появится серверный API.

Решения: Телемост — оба режима (API для Яндекс 360 для бизнеса и ссылка, вставленная
вручную); постоянная комната у ученика и у группы (в отдельном занятии ссылку можно
заменить); у группы своя цена занятия; Холст — ссылки и копирование.

Новые решения: ADR-0011 (группы и групповые занятия), ADR-0012 (видеовстречи и доски),
ADR-0013 (диалоги с ботами).

## Этап 20. Группы учеников

- [x] 20.1 **B** ADR-0011. `identity`: группа (название, состав, архив), ученик может быть в
      нескольких группах, деактивированный ученик выбывает из групп. Фасад `StudentGroups` и
      события `GroupCreated`, `GroupChanged` (название, состав), `GroupArchived` в
      `identity::api`; REST `/api/teacher/groups/**`; AGENTS.md — описание модуля.
- [x] 20.2 **B** `billing`: цена занятия группы (своя таблица по `groupId`), задаётся при
      создании группы и меняется, как цена ученика.
- [x] 20.3 **F** «Ученики» → вкладка «Группы»: создание, состав, цена; в карточке ученика —
      его группы. Выдача задания и сообщение ученикам — выбор группы подставляет её состав.

## Этап 21. Групповые занятия

- [x] 21.1 **B** `schedule`: занятие и серия — для ученика или для группы; участники занятия
      хранятся отдельно (`lesson_participants`), у индивидуального занятия один участник
      (миграция существующих занятий). Состав будущих занятий группы следует за составом группы
      (`GroupChanged`), прошедшие не меняются. Пересечения проверяются у учителя и у каждого
      участника.
- [x] 21.2 **B** Итог группового занятия — посещаемость каждого участника: «был», «пропуск»
      (оплачивается, как у индивидуальных), «предупредил» (не оплачивается). События
      `LessonCompleted` / `LessonCompletionRevoked` — по участнику, события расписания несут
      состав и `groupId`; `billing` списывает цену группы.
- [x] 21.3 **B** Запросы ученика в групповом занятии: «Не приду» (отмена своего участия;
      поздняя — учитель решает, считать ли пропуском) и предложение переноса (учитель переносит
      занятие для всех, уведомляются все участники). Календари (ICS, Google), напоминания и
      сводки главной учитывают группы.
- [x] 21.4 **F** Расписание: ученик или группа при создании занятия и серии, состав в
      карточке занятия, отметка посещаемости, групповые занятия отличаются цветом; у ученика —
      пометка «группа» и «Не приду».

## Этап 22. Видеовстречи: Яндекс Телемост (модуль `meetings`)

- [x] 22.1 **B** ADR-0012. Модуль `meetings` (зависит от `shared`, `identity::api`), схема
      `meetings`: постоянная комната ученика и группы (ссылка, id конференции, как создана).
      `schedule` получает `meetings::api`: ссылка занятия — своя ссылка занятия или комната
      ученика или группы (карточки, напоминания, ICS, Google Календарь). Таблица зависимостей в
      AGENTS.md.
- [x] 22.2 **B** Подключение Яндекса: OAuth 2.0 Яндекс ID (кнопка «Подключить Яндекс»;
      client id/secret в интерфейсе или `TEACHERBOX_MEETINGS_YANDEX_CLIENT_ID/SECRET`; redirect
      `<адрес портала>/api/public/meetings/yandex/callback`; `state` против CSRF; refresh-токен в
      БД; отзыв при отключении) или готовый токен (`TEACHERBOX_MEETINGS_TELEMOST_TOKEN` — для
      проверки и E2E). Создание конференции `POST /conferences` (зал ожидания для учеников —
      настройка учителя), пересоздание ссылки; 401/403 → «нужно переподключить» и уведомление
      учителю; `MockRestServiceServer`; проверка в разделе администратора (`IntegrationCheck`).
- [x] 22.3 **B** Режим без API (личный аккаунт): учитель вставляет ссылку Телемоста (или
      другой видеосвязи) в комнату ученика или группы. «Отправить ссылку» — событие
      `MeetingLinkShared` → `notifications` (ЛК и мессенджеры; `notifications` получает
      `meetings::api`, только события).
- [x] 22.4 **F** «Настройки» → «Видеовстречи»: подключение Яндекса по шагам (приложение в
      Яндекс ID со scope Телемоста, адрес для redirect, client id/secret) или режим без API;
      комната в карточке ученика и группы (создать, заменить, скопировать, отправить).
      Учитель: «Начать урок» в карточке занятия и на главной открывает приложение Телемоста
      (`telemost://…`; на Windows по умолчанию, настройка «Открывать в приложении» хранится на
      устройстве) и доску; рядом — «Открыть в браузере». Ученик: «Войти на урок» на главной и в
      расписании.
- [x] 22.5 **D** README: Яндекс 360 для бизнеса и API, приложение в Яндекс ID, режим без API
      для личного аккаунта; `.env.example`.

## Этап 23. Доски Холст (модуль `boards`)

- [x] 23.1 **B** Модуль `boards` (зависит от `shared`, `identity::api`), схема `boards`: доски
      ученика и группы (название, ссылка; ссылки `app.holst.so` распознаются, допустима любая
      https-ссылка). REST учителя и ученика (свои доски и доски своих групп; тест «чужой ученик
      → 403/404»).
- [x] 23.2 **F** Доски в карточке ученика и группы, «Мои доски» у ученика (главная,
      расписание), доска в карточке занятия и в «Начать урок».
- [x] 23.3 **F** «На доску» для задания (у учителя) и для результата ИИ (черновик задания и
      черновик проверки): выбор доски ученика или группы → материал копируется в буфер обмена
      (форматированный текст и картинка PNG) → доска открывается в новой вкладке с подсказкой
      «нажмите Ctrl+V». Вставку в Холст проверить вручную (нужен аккаунт Холста).
- [x] 23.4 **D** README: доска в Холсте, доступ ученику по ссылке, привязка к ученику;
      ограничения — в ADR-0012.

## Этап 24. Диалоги с ботами: основа

- [x] 24.1 **B** ADR-0013. SPI `shared.chat`: действие бота (id, роль, пункт меню, шаги
      диалога), ввод (текст или нажатая кнопка), ответ (текст и кнопки). Модули реализуют свои
      действия и сами проверяют права, как в REST, и меняют только свои данные; движок в
      `notifications` собирает действия из контекста — как `IntegrationCheck`, без новых
      зависимостей между модулями.
- [x] 24.2 **B** Кнопки в адаптерах: Telegram — inline-клавиатура, `callback_query` и
      `answerCallbackQuery`, меню команд `setMyCommands`; ВКонтакте — inline-клавиатура с
      `payload` в `message_new`; MAX — `inline_keyboard`, `message_callback` и `/answers`.
      Данные кнопки короткие (лимит Telegram — 64 байта) и ссылаются на состояние на сервере.
      Уведомления тоже могут нести кнопки (колонка в очереди доставки).
- [x] 24.3 **B** Движок: только привязанные аккаунты (роль — из `identity`), главное меню по
      роли (`/menu`), состояние диалога в БД с истечением, «Отмена» на любом шаге,
      подтверждение перед изменением данных, постраничный выбор ученика и поиск по имени, дата
      кнопками и время текстом («18:30»). Действия учителя — в аудит (`AuditLog`, «через
      бота»); учитель может выключить управление через бота.
- [x] 24.4 **F** Мастер бота: для ВКонтакте — включить возможности ботов в сообществе;
      вкладка «Мессенджеры» — «Что умеет бот».

## Этап 25. Бот ученика

- [x] 25.1 **B** `schedule`: «Расписание» (ближайшие занятия со ссылкой на встречу), «Отменить
      занятие» и «Перенести занятие» (занятие → дата и время → комментарий → подтверждение →
      запрос учителю), в групповом занятии — «Не приду»; «Мои запросы» (статус, ответ учителя,
      отозвать).
- [x] 25.2 **B** `billing`: «Оплаты» — баланс, цена занятия, последние оплаты и списания.
- [x] 25.3 **B** `meetings` и `boards`: «Войти на урок» (ссылка комнаты) и «Мои доски».

## Этап 26. Бот учителя

- [x] 26.1 **B** `schedule`: «Сегодня» (занятия дня с кнопками «Проведено» и «Пропуск», у
      группы — посещаемость), «Неотмеченные» (прошедшие занятия без итога).
- [x] 26.2 **B** `schedule`: «Запросы» — список и кнопки прямо в уведомлении о запросе:
      «Принять», «Отклонить» с ответом текстом; поздняя отмена — «Считать пропуском?».
- [x] 26.3 **B** `billing`: «Записать оплату» (ученик → сумма: кнопки 1, 4 и 8 занятий по его
      цене или текстом → способ → подтверждение), «Добавить занятие» (проведённое вне
      расписания: ученик или группа → дата → подтверждение → журнал занятий).

## Этап 27. Справка

- [x] 27.1 **F** Раздел «Справка» (`/teacher/help`, `/cabinet/help`, `/admin/help`): статьи в
      Markdown по ролям, оглавление, поиск; пункт в меню пользователя. Язык простой, без
      технических терминов: короткие шаги «что нажать» и ответы на частые вопросы.
- [x] 27.2 **F** Статьи учителя: первые шаги, ученики и приглашения, группы, расписание и
      запросы, видеовстречи, доски, задания, ИИ-помощник, оплаты, уведомления и боты, что умеет
      бот, календари (ICS, Google), настройки, частые вопросы. Ученика: вход и пароль,
      расписание и перенос, урок и доска, задания, оплаты, бот. Администратора: журнал и
      диагностика.
- [x] 27.3 **F** Ссылки на справку в основных разделах: значок «?» в заголовке открывает
      статью в боковой панели, не уводя со страницы; в мастерах — «Подробнее»; бот отвечает на
      `/help` ссылкой на справку. Тест: каждая ссылка ведёт на существующую статью.
