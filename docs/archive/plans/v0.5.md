# Версия 0.5 — архив плана (этапы 40–47)

Цели: доделать вид разделов с вкладками и нижнюю панель на телефоне, упростить оплаты (без
способа оплаты), дать учителю удалять и восстанавливать занятия, показать ученику занятое время
учителя и проверять перенос по нему, иконки на кнопках ботов, свой цвет портала из палитры и
настройки портала в интерфейсе администратора. Этапы идут от простых и независимых к большим:
сначала правки интерфейса и оплат, затем расписание, боты и цвет, в конце — настройки
администратора (новое решение, ADR-0016) и выпуск.

Итоги разбора:

- **Вкладки.** В «Учениках» и «Уведомлениях» панель вкладок PrimeNG рисует свой белый фон под
  карточкой и до конца страницы; сами вкладки — серые на белой полосе и не похожи на остальной
  интерфейс.
- **Нижняя панель.** У учителя четыре раздела и «Ещё», «Оплаты» — только в «Ещё»; пункты
  прижаты к краям неравномерно.
- **Способ оплаты** (наличные, карта, перевод, другое) нигде не используется для расчётов, но
  спрашивается в диалоге и боте и показывается в журнале и отчёте.
- **Занятия** можно только отменить: ошибочно созданное занятие остаётся в календаре и отчётах
  отменённым, а отменённое вернуть нельзя — только создать заново. Регулярные занятия создаются
  по отметке «создано до», поэтому удалённое занятие серии не появится снова.
- **Перенос учеником** не проверяет, свободно ли время: учитель узнаёт о пересечении только при
  одобрении. Ученик не видит, когда учитель занят.
- **Боты** — кнопки только текстом.
- **Цвет портала** — одна из шести палитр; свой цвет выбрать нельзя.
- **Настройки** (58 переменных в `.env.example`) меняются только в `.env` на сервере с
  перезапуском контейнера; администратор видит часть из них в «Состоянии», но не меняет.

Решения: удалять можно только непроведённые занятия (запланированные и отменённые без
списания); проведённое, пропуск и отмену со списанием сначала снимают с отметки или
восстанавливают. Ученик видит занятое время учителя — чужие занятия и занятость Google
Календаря — без имён и тем; перенос на занятое время отклоняется сразу, учитель при одобрении
получает ту же проверку. Свой цвет — любой, с предупреждением о плохом контрасте. Администратор
меняет все переменные приложения; значения из интерфейса важнее `.env`, применяются после
перезапуска, секреты задаются заново и не показываются; переменные Docker — только для чтения.

Новое решение: ADR-0016 (настройки портала в интерфейсе администратора).

## Этап 40. Вкладки и нижняя панель

- [x] 40.1 **F** Разделы с вкладками («Ученики», «Уведомления» и остальные): без белого фона
      панелей вкладок под карточкой, вкладки — в стиле портала (подчёркивание цветом портала,
      одинаковые отступы, на телефоне — прокрутка без обрезки). Светлая и тёмная тема.
- [x] 40.2 **F** Нижняя панель на телефоне: у учителя пять разделов («Главная», «Расписание»,
      «Ученики», «Задания», «Оплаты») и «Ещё»; все пункты равной ширины на всю ширину экрана, у
      ученика тоже.

## Этап 41. Оплаты без способа оплаты

- [x] 41.1 **B** Способ оплаты убран из модели, API, событий, бота «Записать оплату» (без шага
      выбора способа) и уведомлений; миграция `billing` удаляет колонку и её проверку. Старые
      копии восстанавливаются (миграции применяются после восстановления).
- [x] 41.2 **F** Диалог оплаты, журнал ученика, отчёт за месяц, справка — без способа оплаты.

## Этап 42. Удаление и восстановление занятий

- [x] 42.1 **B** Удаление непроведённого занятия (запланированного или отменённого без списания):
      `DELETE /api/teacher/schedule/lessons/{id}`; проведённое, пропуск, отмена со списанием —
      `422 schedule.lesson-charged`. Событие `LessonDeleted` в `schedule::api`: занятие уходит из
      Google Календаря и ленты ICS, ученик (участники группы) получает уведомление, если занятие
      ещё не прошло и не было отменено; открытые запросы по занятию закрываются. Занятие серии
      удаляется только само.
- [x] 42.2 **B** Восстановление отменённого занятия: `POST .../lessons/{id}/restore` — снова
      запланировано (участники группы — ожидаются), проверка пересечения с подтверждением «всё
      равно», у отмены со списанием начисление снимается (`LessonCompletionRevoked`). Событие
      `LessonRestored`: Google Календарь, ICS, уведомление ученику. Прошедшее занятие
      восстанавливается и ждёт отметки.
- [x] 42.3 **F** Карточка занятия: «Удалить» (с подтверждением) для запланированных и отменённых
      без списания, «Восстановить» для отменённых; календарь и главная обновляются.

## Этап 43. Занятое время учителя для ученика

- [x] 43.1 **B** `GET /api/me/schedule/busy?from&to` — занятое время учителя: занятия других
      учеников и групп и занятость Google Календаря (если учитель разрешил её читать) —
      только интервалы, без имён, тем и ссылок. Тест: ученик не видит данных других учеников.
- [x] 43.2 **B** Проверка переноса: запрос ученика (в кабинете и в боте) на занятое время —
      `409 schedule.slot-busy` с понятным текстом; при одобрении учителем — та же проверка с
      подтверждением «всё равно перенести».
- [x] 43.3 **F** Календарь ученика показывает занятое время учителя фоном «Занято»; диалог переноса
      сообщает о занятом времени до отправки и не даёт его выбрать.

## Этап 44. Свой цвет портала

- [x] 44.1 **B** Цвет портала: одна из палитр или свой цвет `#rrggbb` (проверка формата); в
      публичной информации портала — как есть.
- [x] 44.2 **F** Выбор цвета: готовые палитры и «Свой» — палитра PrimeNG ColorPicker и поле HEX;
      оттенки 50–950 строятся из цвета для обеих тем; предпросмотр кнопки и предупреждение, если
      контраст текста на кнопке ниже 3:1 (WCAG для крупного текста и элементов;
      при 4.5:1 предупреждение получали бы и готовые палитры PrimeNG).

## Этап 45. Иконки на кнопках ботов

- [x] 45.1 **B** Эмодзи на кнопках ботов Telegram, ВКонтакте и MAX: у каждого действия
      (`ChatAction.icon()`) — своя иконка в меню, у общих кнопок («Меню», «Отмена», «Да»/«Нет»,
      «Принять»/«Отклонить», «Проведено»/«Пропуск» и т. п.) — свои (`shared.chat.ChatIcons`);
      кнопки с данными (ученики, занятия, даты) — без иконок, чтобы по несколько помещались в ряд.

## Этап 46. Настройки портала у администратора

- [x] 46.1 **B** Каталог настроек: все переменные `TEACHERBOX_*` с группой, описанием, типом
      (строка, число, да/нет, длительность, cron, URL, список), признаком секрета и «только
      Docker» (порт, версия образа, лимиты памяти и процессора — только чтение). Вход учителя
      (логин, пароль, сброс пароля) — только чтение: иначе администратор получил бы доступ к
      данным учеников (ADR-0010). Тест: каталог совпадает с `.env.example`.
- [x] 46.2 **B** Хранилище: `<data-dir>/config/settings.properties` (вне базы — нужно до её
      открытия), при запуске подключается источником свойств важнее переменных окружения. В
      резервные копии не входит: восстановление копии не меняет настроек сервера.
- [x] 46.3 **B** `/api/admin/settings`: значения и источник (по умолчанию, `.env`, интерфейс; у
      секретов — только «задан»), изменение и возврат к `.env` с паролем администратора, проверка
      значений по типу, запись в журнал аудита без значений, затем перезапуск, как при
      восстановлении копии (без Docker — «перезапустите вручную»).
- [x] 46.4 **F** Раздел «Настройки» у администратора: группы, поле по типу, отметка «изменено в
      интерфейсе», «Вернуть как в .env», «Сохранить и перезапустить» с ожиданием перезапуска.
- [x] 46.5 ADR-0016, `docs/operations.md`, README.
