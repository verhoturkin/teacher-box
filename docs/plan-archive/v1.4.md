# Версия 1.4 — архив плана (этапы 34–39)

Цели: редизайн и улучшение UX/UI на компьютере и телефоне, свой логотип портала, закреплённая
шапка, упрощение кода фронтенда и тестов. Этапы идут так, чтобы следующие строились на
предыдущих: сначала чистим код и форматирование (дальнейшие изменения — на чистой базе), затем
дизайн-система (сетка, токены, темы), затем каркас приложения (шапка, нижняя панель), затем
мобильные экраны и главная, в конце — справка и выпуск.

Итоги разбора (компьютер 1366 px и телефон 375 px):

- **Телефон.** Меню пользователя в шапке обрезано у правого края. Таблицы (ученики, оплаты,
  задания) прокручиваются по горизонтали, кнопки действий в строке ученика не видны. Недельная
  сетка расписания нечитаема (7 колонок по ~40 px). Кнопки страниц переносятся в несколько строк,
  четыре карточки сводки «Оплат» занимают весь экран до списка. Шапка уезжает при прокрутке.
- **Компьютер.** Узкий контент и много пустого места; пустые разделы обрываются без подсказки.
  На главной сверху «С чего начать» с зачёркнутыми пунктами, «Сегодня» ниже; нет быстрых
  действий (оплату записывают только из раздела «Оплаты»).
- **Единообразие.** Отступы, радиусы, размеры кнопок и заголовков карточек заданы по месту в
  ~50 компонентах; одни кнопки маленькие, другие обычные, ссылки то подчёркнуты, то нет.
- **Код.** 186 файлов (~19 тыс. строк) и 122 теста (~11 тыс. строк). Одинаковая настройка
  TestBed в 63 тестах, работа с `localStorage` повторяется в 4 местах, стили строк таблиц — в
  нескольких компонентах; часть файлов не отформатирована.
- **Название портала** меняется с версии 1.3 («Настройки» → «Портал»); в 1.4 к нему добавляется
  свой логотип.

Новое решение: ADR-0015 (дизайн-система и мобильный интерфейс).

Решения: на телефоне — нижняя панель разделов, карточки вместо таблиц, расписание списком по
дням, диалоги на весь экран; дизайн по сетке 4/8 px с едиными радиусами, кнопками и
типографикой; шире контент на больших экранах; переключатель темы (светлая, тёмная, как в
системе); цвет портала и свой логотип в настройках; понятные пустые состояния; на главной —
быстрые действия, ближайшее занятие сверху и компактное «С чего начать». Рефакторинг: удаление
мёртвого кода (knip), общие помощники тестов, единое форматирование Prettier с проверкой.

## Этап 34. Чистка фронтенда

- [x] 34.1 **F** Единое форматирование: Prettier по всему `frontend/src` и `e2e`, проверка
      `prettier --check` в `npm run lint` (и в хуке).
- [x] 34.2 **F** Мёртвый код: knip (неиспользуемые файлы, экспорты, зависимости, типы) — удалить
      найденное, проверку knip — в `npm run lint`; неиспользуемые глобальные стили и классы.
- [x] 34.3 **F** Общие помощники: настройка TestBed для компонентов и сервисов (`@testing/`)
      вместо копий в тестах, общие фикстуры; хранилище браузера (`localStorage` с защитой от
      ошибок) — один сервис вместо четырёх копий. Проверки тестов не ослабляются, пороги покрытия
      те же.

## Этап 35. Дизайн-система

- [x] 35.1 **F** Токены: сетка 4/8 px (отступы), радиусы, тени, размеры кнопок и полей,
      типографика заголовков — в пресете PrimeNG и `styles.scss`; компоненты используют токены и
      общие классы (карточка, заголовок страницы, панель действий, строка таблицы) вместо стилей по
      месту. Ширина контента: до 1440 px, узкие страницы (формы, настройки) — уже.
- [x] 35.2 **F** Тема: переключатель «Светлая / Тёмная / Как в системе» в меню пользователя
      (хранится на устройстве); проверка контраста в тёмной теме.
- [x] 35.3 **B/F** Цвет портала: учитель выбирает акцентный цвет из готовых палитр («Настройки» →
      «Портал»); хранится в настройках портала (`platform`), отдаётся в `/api/public/portal`,
      применяется при запуске.
- [x] 35.4 **F** Пустые состояния: общий компонент (значок, пояснение, кнопка первого действия)
      во всех списках и разделах.

## Этап 36. Каркас: шапка, меню, логотип

- [x] 36.1 **F** Шапка закреплена наверху при прокрутке; на телефоне компактная (логотип и
      название, колокольчик, меню пользователя) и помещается по ширине.
- [x] 36.2 **F** Нижняя панель на телефоне: 4 главных раздела роли и «Ещё» (остальные разделы,
      справка, настройки, аккаунт, выход); у ученика и администратора — свои разделы.
- [x] 36.3 **B** Свой логотип: загрузка PNG, JPEG, WebP или SVG до 1 МБ в «Настройки» →
      «Портал» (файл — в хранилище `platform`, попадает в резервные копии, удаляется при сбросе);
      `GET /api/public/portal/logo` (SVG отдаётся с `Content-Security-Policy: sandbox`), удаление.
- [x] 36.4 **F** Логотип в шапке, на страницах входа и приглашения и значком во вкладке браузера;
      без логотипа — прежний значок.

## Этап 37. Мобильные экраны

- [x] 37.1 **F** Карточки вместо таблиц на узком экране: ученики, группы, оплаты, задания,
      проверка работ, журнал оплат ученика, уведомления, копии, разделы администратора и ИИ
      (класс `tb-cards` и подписи `data-label`); кнопки действий — внизу карточки: они иконками,
      помещаются и удобнее меню «⋯».
- [x] 37.2 **F** Расписание на телефоне: по умолчанию список по дням, плавающая кнопка «+»
      (занятие); на компьютере — неделя.
- [x] 37.3 **F** Диалоги на телефоне на весь экран, кнопки действий закреплены внизу; формы —
      поля во всю ширину, удобные для пальца размеры.
- [x] 37.4 **F** Страницы на телефоне: кнопки заголовка растягиваются на всю ширину, сводки
      «Оплат» — по две в ряд, длинные тексты в карточках (журнал, ошибки) — под подписью; разделы
      учителя и администратора проверены на 375 px, раздел ученика проверяет E2E (39.2).

## Этап 38. Главная

- [x] 38.1 **F** Главная учителя: ближайшее занятие сверху («Начать урок», доска), быстрые
